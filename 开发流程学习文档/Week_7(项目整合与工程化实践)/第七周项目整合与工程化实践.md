### 1.1 Git 版本控制体系回顾

Git 是分布式版本控制系统的核心工具，贯穿项目开发全生命周期。本节回顾 Git 四区模型、Feature Branch 工作流及常用操作速查。

#### Git 核心概念

Git 的四个核心区域构成了数据流转的完整链路：

表 7-4：Git 四区核心概念对照

| 区域 | 英文名 | 说明 | 典型操作 |
|------|--------|------|----------|
| **工作区** | Working Directory | 本地文件系统中可见的项目目录 | 编辑文件、`git status` |
| **暂存区** | Staging Area (Index) | 下次提交将要包含的文件快照 | `git add`、`git restore --staged` |
| **本地仓库** | Local Repository | 本地保存的所有提交历史 | `git commit`、`git log` |
| **远程仓库** | Remote Repository | 托管在服务器上的共享仓库 | `git push`、`git pull` |

数据流转路径：**工作区 → `git add` → 暂存区 → `git commit` → 本地仓库 → `git push` → 远程仓库**

#### Feature Branch 工作流

**Solo 开发者版**（适用于当前项目阶段）：

1. 从 main 创建 feature 分支：`git checkout -b feature/alert`
2. 在 feature 分支上开发完成
3. 合并回 main：`git checkout main && git merge feature/alert`
4. 推送到远程：`git push origin main`
5. 删除已合并的 feature 分支：`git branch -d feature/alert`

**团队协作版**（适用于多人协作场景）：

1. 从 develop 创建 feature 分支
2. 开发完成后提交 Pull Request
3. 代码审查通过后合并到 develop
4. develop 测试通过后合并到 release
5. release 验证后合并到 main 并打标签

表 7-5：两种工作流对比

| 维度 | Solo 开发者版 | 团队协作版 |
|------|-------------|-----------|
| 分支数量 | main + feature | main + develop + feature + release |
| 合并目标 | feature → main | feature → develop → release → main |
| 代码审查 | 可选 | **必须**（Pull Request） |
| 冲突概率 | 低 | 中等 |
| 适用场景 | 个人项目、学习阶段 | 多人协作、生产项目 |

表 7-6：Git 常用操作速查表

| | `git clone <url>` | 克隆远程仓库 |
| **提交** | `git add .` | 暂存所有变更 |

### 1.2 Spring Boot 项目架构整合

IoT-Platform 采用经典的**分层架构**设计，各层职责明确、依赖单向。本节从架构图、包结构、配置管理三个维度整合项目架构认知。

#### 项目分层架构

IoT-Platform 四层架构自上而下调用，横切关注点贯穿各层：

- **Controller 层**：接收请求、参数校验、调用 Service、返回 Result\<T\>
  - DeviceController | DeviceDataController | DeviceTypeController | DictMetricController
- **Service 层**：业务逻辑、事务控制、异常抛出、规则引擎
  - DeviceService | AlertService | DictMetricService | AlertRuleEngine | DeviceMonitorTask
- **Mapper 层**：数据访问、BaseMapper 继承、自定义 SQL 统计查询
  - DeviceMapper | AlertMapper | DeviceDataMapper | DeviceTypeMapper | DictMetricMapper
- **Entity 层**：实体映射、@TableName、@TableField、校验注解
  - Device | DeviceType | DeviceData | Alert | DictMetric

横切关注点：
- **common/**：Result\<T\> | BusinessException | GlobalExceptionHandler | ResultCode
- **config/**：MybatisPlusConfig | MyMetaObjectHandler | CorsConfig
- **dto/**：AlertRuleConfig | AlertRuleDefinition | BatchHandleAlertDTO

### 2.1 数据库设计回顾

#### ER 图与表关系

IoT-Platform 数据库 **iot_device_db** 包含 5 张核心表，关系如下：

- **device_types** (1) → (N) **devices**：一个设备类型下有多台设备
- **devices** (1) → (N) **device_data**：一台设备有多条采集数据
- **devices** (1) → (N) **alerts**：一台设备有多条告警记录
- **dict_metric**：独立字典表，存储指标元数据

#### DDL 建表语句整合

**device_types 表**（设备类型）：

```sql
CREATE TABLE device_types (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL COMMENT '类型名称',
    code VARCHAR(50) NOT NULL UNIQUE COMMENT '类型编码',
    description TEXT COMMENT '类型描述',
    alert_rule_config JSON COMMENT '默认告警规则配置',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) COMMENT '设备类型表';
```

**devices 表**（设备）：

```sql
CREATE TABLE devices (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL COMMENT '设备名称',
    device_code VARCHAR(50) NOT NULL UNIQUE COMMENT '设备编码',
    type_id BIGINT NOT NULL COMMENT '设备类型ID',
    status TINYINT DEFAULT 0 COMMENT '0-离线 1-在线',
    alert_rule_config JSON COMMENT '设备级告警规则配置',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (type_id) REFERENCES device_types(id)
) COMMENT '设备表';
```

**device_data 表**（设备数据）：

```sql
CREATE TABLE device_data (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    device_id BIGINT NOT NULL COMMENT '设备ID',
    metric_key VARCHAR(50) NOT NULL COMMENT '指标键名',
    metric_value DECIMAL(10,2) NOT NULL COMMENT '指标值',
    collect_time DATETIME NOT NULL COMMENT '采集时间',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP
) COMMENT '设备数据表';
```

**alerts 表**（告警）：

```sql
CREATE TABLE alerts (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    device_id BIGINT NOT NULL COMMENT '设备ID',
    alert_level TINYINT NOT NULL COMMENT '告警级别1-5',
    metric_key VARCHAR(50) NOT NULL COMMENT '指标键名',
    message TEXT NOT NULL COMMENT '告警消息',
    is_handled TINYINT DEFAULT 0 COMMENT '0-未处理 1-已处理',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (device_id) REFERENCES devices(id)
) COMMENT '告警表';
```

**dict_metric 表**（指标字典）：

```sql
CREATE TABLE dict_metric (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    metric_key VARCHAR(50) NOT NULL UNIQUE COMMENT '指标键名',
    metric_name VARCHAR(100) NOT NULL COMMENT '指标名称',
    unit VARCHAR(20) COMMENT '指标单位',
    description TEXT COMMENT '指标描述',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) COMMENT '指标字典表';
```

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        return Result.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining("; "));
        return Result.error(400, message);
    }

    @ExceptionHandler(Exception.class)

        return Result.error(500, "服务器内部错误");
    }
}
```

#### DictMetricService 内存缓存

```java
@Service
public class DictMetricServiceImpl extends ServiceImpl<DictMetricMapper, DictMetric>
        implements DictMetricService {

    private final ConcurrentHashMap<String, DictMetric> metricCache = new ConcurrentHashMap<>();

    @PostConstruct
    public void initCache() {
        list().forEach(m -> metricCache.put(m.getMetricKey(), m));
    }

    public void refreshCache() {
        metricCache.clear();
        initCache();
    }

    public String getMetricName(String metricKey) {
        return metricCache.getOrDefault(metricKey, new DictMetric()).getMetricName();
    }
}
```

> **设计价值**：ConcurrentHashMap 保证线程安全，@PostConstruct 启动时加载，查询走内存不查数据库，性能提升显著。

```java
                .eq(Device::getStatus, 1)
                .last("AND id NOT IN " +
                    "(SELECT device_id FROM device_data WHERE collect_time > '" + cutoff + "')")
        );
        if (!offlineDevices.isEmpty()) {
            alertService.createOfflineAlerts(offlineDevices);
        }
    }
}
```

> **关键设计**：cron 表达式和离线阈值均外部化到 application.yml，不同环境可配置不同值。

```java
@PostMapping
public Result<Void> create(@RequestBody @Valid DeviceDataDTO dto) {
    DeviceData data = new DeviceData();
    data.setDeviceId(dto.getDeviceId());
    data.setMetricKey(dto.getMetricKey());
    data.setMetricValue(dto.getMetricValue());
    data.setCollectTime(dto.getCollectTime());
    deviceDataService.saveWithAlertCheck(data);
    return Result.success(null);
}

@Transactional(rollbackFor = Exception.class)
public void saveWithAlertCheck(DeviceData data) {
    Device device = getDeviceOrThrow(data.getDeviceId());
    save(data);
    alertRuleEngine.evaluateAndCreateAlerts(device, data);
}

public void evaluateAndCreateAlerts(Device device, DeviceData data) {
    AlertRuleConfig config = getEffectiveRuleConfig(device);
    List<AlertRuleDefinition> rules = config.getRules().stream()
            .filter(r -> r.getMetricKey().equals(data.getMetricKey()))
            .sorted(Comparator.comparingInt(AlertRuleDefinition::getLevel))
            .collect(Collectors.toList());

    Map<String, Alert> activeAlertMap = getActiveAlertMap(device.getId());

    List<Alert> newAlerts = new ArrayList<>();
    for (AlertRuleDefinition rule : rules) {
        if (isThresholdExceeded(rule, data.getMetricValue())) {
            Alert existing = activeAlertMap.get(rule.getMetricKey());
            if (shouldCreateAlert(rule, existing)) {
                Alert alert = buildAlert(device, rule, data);
                newAlerts.add(alert);
            }
        }
    }

    if (!newAlerts.isEmpty()) {
        alertService.saveBatch(newAlerts);
    }
}
```
