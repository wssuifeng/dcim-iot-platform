## 1.1 骨架 vs 完整模块的差距

在第四周，我们搭建了 IoT-Platform 的项目骨架——有了数据库、实体类、Mapper 接口、Service 接口和空的 Controller。但这个骨架还**不能做任何事情**，因为：

| 对比维度 | 骨架状态（第四周结束） | 完整模块（第五周目标） |
|---------|:-------------------|:-------------------|
| Controller | 空类，没有任何接口方法 | 完整的 CRUD + 业务查询接口 |
| 请求校验 | 无——任何参数都能提交 | @Valid 注解校验 + 自定义校验逻辑 |
| 异常处理 | 无——报错直接返回 500 | 统一异常处理，返回友好的错误信息 |
| Service 实现 | 3个 ServiceImpl 缺少 @Service 注解 | 全部完善，含自定义业务方法 |

| 跨域配置 | 无——前端无法调用 | CORS 配置完成，支持前端联调 |
| 配置文件 | 包名引用错误 | 修正为 com.example.platform |

**📝 修复后（添加注解）：**

```java
        implements DeviceTypeService {
```

> **💡 说明**：Spring Boot 的组件扫描机制会自动扫描 `@SpringBootApplication` 注解所在包及其子包下的所有类。但只有标注了 `@Component`（或其派生注解 `@Service`、`@Repository`、`@Controller`）的类才会被注册为 Spring Bean。缺少 `@Service` 注解意味着这些类不会被 Spring 容器管理，当 Controller 尝试通过 `@Autowired` 注入时会抛出 `NoSuchBeanDefinitionException`。

**验证方法**：在任意 Controller 中注入这些 Service，启动项目不报错即修复成功：

```java

@Autowired
private AlertService alertService;
```

## 2.3 启用 MybatisPlusConfig 分页插件

**▶ 任务要求**

- 取消 `MybatisPlusConfig.java` 中所有被注释的代码
- 确保分页拦截器正确注册
- 修复后编写简单分页查询验证

**📁 文件路径：src/main/java/com/example/platform/config/MybatisPlusConfig.java**

**📝 修复前（被注释）：**

```java
// @Configuration
// public class MybatisPlusConfig {
//
//     @Bean
//     public MybatisPlusInterceptor mybatisPlusInterceptor() {
//         MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
//         interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
//         return interceptor;
//     }
// }
```

**📝 修复后（取消注释）：**

```java
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

> **💡 说明**：MyBatis-Plus 的分页功能依赖 `PaginationInnerInterceptor` 拦截器。没有这个拦截器，`Page` 对象虽然能创建，但 `selectPage` 方法不会自动添加 `LIMIT` 语句，`getTotal()` 也不会执行 `COUNT` 查询，导致分页功能完全失效。`DbType.MYSQL` 参数告诉插件生成 MySQL 方言的分页 SQL（即 `LIMIT offset, size`）。

**验证方法**：在测试类或 Controller 中执行分页查询：

```java
Page<Device> page = new Page<>(1, 10);
Page<Device> result = deviceService.page(page);
System.out.println("总记录数：" + result.getTotal());
System.out.println("当前页数据量：" + result.getRecords().size());
```

如果 `getTotal()` 返回正确的记录数（而非0），说明分页插件已生效。

## 2.4 实现 MetaObjectHandler 时间自动填充

**▶ 任务要求**

- 创建 `MyMetaObjectHandler` 类，实现 `MetaObjectHandler` 接口
- 实现 `insertFill` 方法，自动填充 `createTime`
- 实现 `updateFill` 方法，自动填充 `updateTime`
- 验证新增/更新设备时时间字段自动填充

**📁 文件路径：src/main/java/com/example/platform/config/MyMetaObjectHandler.java**

**📝 参考代码：**

```java
package com.example.platform.config;

import com.baomidou.mybatisplus.core.handlers.MetaObjectHandler;
import org.apache.ibatis.reflection.MetaObject;
import org.springframework.stereotype.Component;

import java.time.LocalDateTime;

@Component
public class MyMetaObjectHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        this.setFieldValByName("createTime", LocalDateTime.now(), metaObject);
        this.setFieldValByName("updateTime", LocalDateTime.now(), metaObject);
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        this.setFieldValByName("updateTime", LocalDateTime.now(), metaObject);
    }
}
```

**前置条件——确认实体类字段注解：**

确保 `Device.java` 和 `DeviceType.java` 中的时间字段已配置填充策略：

```java
@TableField(value = "create_time", fill = FieldFill.INSERT)
private LocalDateTime createTime;

@TableField(value = "update_time", fill = FieldFill.INSERT_UPDATE)
private LocalDateTime updateTime;
```

> **💡 说明**：`MetaObjectHandler` 是 MyBatis-Plus 提供的自动填充机制。当实体字段标注了 `fill = FieldFill.INSERT` 时，执行 `insert` 操作会自动触发 `insertFill` 方法；标注了 `fill = FieldFill.INSERT_UPDATE` 时，执行 `insert` 和 `update` 都会触发。`setFieldValByName` 方法的三个参数分别是：字段名、填充值、元数据对象。这样业务代码中就不需要手动调用 `device.setCreateTime(LocalDateTime.now())` 了。

> **⚠️ 注意**：`@Component` 注解不能少！`MetaObjectHandler` 实现类必须注册为 Spring Bean，MyBatis-Plus 才能在运行时找到它。如果忘记加 `@Component`，自动填充不会生效，也不会报错——这是非常隐蔽的问题。

**验证方法**：

```java
Device device = new Device();
device.setDeviceName("测试设备");
device.setDeviceCode("TEST-001");
deviceService.save(device);
System.out.println("创建时间：" + device.getCreateTime());

device.setLocation("新位置");
deviceService.updateById(device);
System.out.println("更新时间：" + device.getUpdateTime());
```

如果 `createTime` 和 `updateTime` 不为 null，说明自动填充生效。

### 📚 知识准备：RESTful API 设计原则

在实现 Controller 之前，先理解 RESTful 设计的核心思想：

**REST（Representational State Transfer）** 是一种软件架构风格，核心原则是**把一切视为资源**，通过 HTTP 方法对资源进行操作。

| HTTP 方法 | 语义 | 幂等性 | 安全性 | 示例 |
|-----------|------|--------|--------|------|
| `GET` | 查询资源 | 是 | 是 | `GET /devices` 查询设备列表 |
| `POST` | 创建资源 | 否 | 否 | `POST /devices` 新增设备 |
| `PUT` | 更新资源（全量替换） | 是 | 否 | `PUT /devices/1` 更新ID为1的设备 |
| `DELETE` | 删除资源 | 是 | 否 | `DELETE /devices/1` 删除ID为1的设备 |

> **💡 说明**：
> - **幂等性**：多次调用产生相同结果。GET 查100次结果一样，DELETE 删100次和删1次效果一样。POST 不是幂等的——调用2次会创建2条记录。
> - **安全性**：是否修改服务器数据。GET 只读不写，是安全的；其他方法都会修改数据。
> - **无状态性**：每个请求必须包含所有必要信息，服务器不保存客户端状态。这意味着任何请求都可以独立理解，不依赖之前的请求。

**URL 设计规范：**

```
GET    /api/devices          → 查询设备列表
GET    /api/devices/{id}     → 查询单个设备
```

### 任务一：添加 Bean Validation 参数校验

**▶ 任务要求**

- 在 `Device` 实体类上添加校验注解
- 在 Controller 方法参数上添加 `@Valid` 注解

**📁 文件路径：src/main/java/com/example/platform/entity/Device.java**

**📝 修改实体类，添加校验注解：**

```java
package com.example.platform.entity;

import com.baomidou.mybatisplus.annotation.*;
import jakarta.validation.constraints.*;
import lombok.Data;

import java.time.LocalDateTime;

@Data
@TableName("devices")
public class Device {

    @TableId(value = "id", type = IdType.AUTO)
    private Integer id;

    @NotBlank(message = "设备名称不能为空")
    @Size(max = 100, message = "设备名称长度不能超过100个字符")
    @TableField("device_name")
    private String deviceName;

    @NotBlank(message = "设备编码不能为空")
    @Size(max = 50, message = "设备编码长度不能超过50个字符")
    @TableField("device_code")
    private String deviceCode;

    @TableField("type_id")
    private Integer typeId;

    @Min(value = 0, message = "设备状态值不能小于0")
    @Max(value = 2, message = "设备状态值不能大于2")
    @TableField("status")
    private Integer status;

    @Size(max = 200, message = "设备位置长度不能超过200个字符")
    @TableField("location")
    private String location;

    @Size(max = 50, message = "IP地址长度不能超过50个字符")
    @TableField("ip_address")
    private String ipAddress;

    @TableField("last_online_time")
    private LocalDateTime lastOnlineTime;

    @TableField(value = "create_time", fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(value = "update_time", fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

**📁 修改 Controller，添加 @Valid 注解：**

```java
@PostMapping
public Result<Void> save(@Valid @RequestBody Device device) {
    boolean saved = deviceService.save(device);
    if (!saved) {
        return Result.error("新增设备失败");
    }

@PutMapping("/{id}")

        return Result.error("设备不存在，无法更新");
    }

    boolean updated = deviceService.updateById(device);
    if (!updated) {
        return Result.error("更新设备失败");
    }
    return Result.success();
}
```

> **💡 说明**：
> - `@Valid` 注解触发 Bean Validation 校验。Spring 在将 JSON 反序列化为对象后，会自动检查所有校验注解
> - `@NotBlank` = 不能为 null、不能为空字符串、不能为纯空格（适用于 String 类型）
> - `@NotNull` = 不能为 null（适用于所有类型）
> - `@Size` = 限制字符串长度或集合大小
> - `@Min` / `@Max` = 限制数值范围
> - 校验失败时，Spring 会抛出 `MethodArgumentNotValidException`，我们将在任务三中统一处理

> **⚠️ 注意**：`@NotBlank` 和 `@NotNull` 的区别——`@NotBlank` 只能用在 String 类型上，`@NotNull` 可以用在任何类型上。对于 `@NotBlank`，`""` 和 `"   "` 都不通过；对于 `@NotNull`，`""` 是合法的。

### 任务三：实现 GlobalExceptionHandler（@RestControllerAdvice）

**▶ 任务要求**

- 创建全局异常处理器，使用 `@RestControllerAdvice` 注解
- 处理参数校验异常（`MethodArgumentNotValidException`）
- 处理业务异常（`BusinessException`）
- 处理资源未找到异常（`DeviceNotFoundException`）
- 处理其他未预期异常（`Exception`）

**📁 文件路径：src/main/java/com/example/platform/common/exception/GlobalExceptionHandler.java**

**📝 参考代码：**

```java
package com.example.platform.common.exception;

import com.example.platform.common.Result;
import lombok.extern.slf4j.Slf4j;
import org.springframework.http.HttpStatus;
import org.springframework.validation.FieldError;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.util.stream.Collectors;

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleValidationException(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(FieldError::getDefaultMessage)
                .collect(Collectors.joining("; "));
        log.warn("参数校验失败: {}", message);
        return Result.error(400, message);
    }

    @ExceptionHandler(DeviceNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public Result<Void> handleDeviceNotFound(DeviceNotFoundException e) {
        log.warn("设备未找到: {}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(BusinessException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public Result<Void> handleBusinessException(BusinessException e) {
        log.warn("业务异常: {}", e.getMessage());
        return Result.error(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public Result<Void> handleException(Exception e) {
        log.error("系统异常: ", e);
        return Result.error(500, "服务器内部错误");
    }
}
```

> **💡 说明**：
> - `@RestControllerAdvice` = `@ControllerAdvice` + `@ResponseBody`，表示这是一个全局的控制器增强类，且返回值自动序列化为 JSON
> - `@ExceptionHandler` 指定该方法处理哪种异常类型
> - 异常处理器的匹配顺序：精确匹配优先。`DeviceNotFoundException` 会优先被 `handleDeviceNotFound` 处理，而不是 `handleBusinessException`，因为前者更具体
> - `@ResponseStatus` 设置 HTTP 响应状态码，让客户端能根据状态码判断请求是否成功
> - 校验异常的消息拼接：将所有字段的校验错误用分号连接，一次性返回给前端

### 📚 知识准备：LambdaQueryWrapper vs 原生 MyBatis

在第三周，我们学习了原生 MyBatis 的动态 SQL：

```xml
<select id="findByNameLike" resultType="Device">
    SELECT * FROM devices WHERE device_name LIKE CONCAT('%', #{name}, '%')
</select>
```

MyBatis-Plus 提供了 `LambdaQueryWrapper`，用 Java 代码替代 XML：

```java
LambdaQueryWrapper<Device> wrapper = new LambdaQueryWrapper<>();
wrapper.like(Device::getDeviceName, name);
List<Device> devices = deviceMapper.selectList(wrapper);
```

| 对比维度 | 原生 MyBatis XML | LambdaQueryWrapper |
|---------|-----------------|-------------------|
| 字段名安全 | 字符串硬编码，拼写错误运行时才发现 | Lambda 引用，编译时检查 |
| IDE 支持 | XML 中无代码提示 | 完整的代码提示和重构支持 |
| 复杂条件 | 灵活，适合多表关联 | 适合单表条件组合 |
| 学习曲线 | 需要掌握 XML 标签语法 | 链式调用，更直观 |

> **💡 说明**：`Device::getDeviceName` 是 Java 8 的方法引用（Lambda 表达式）。MyBatis-Plus 通过序列化 Lambda 表达式来获取属性名 `deviceName`，再通过配置的命名策略转换为数据库字段名 `device_name`。这样即使重构时修改了属性名，编译器也会报错提醒，而不会像字符串那样默默出错。

```java
package com.example.platform.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.conditions.update.LambdaUpdateWrapper;
import com.baomidou.mybatisplus.extension.service.impl.ServiceImpl;
import com.example.platform.entity.Device;
import com.example.platform.mapper.DeviceMapper;
import com.example.platform.service.DeviceService;
import org.springframework.stereotype.Service;

import java.time.LocalDateTime;
import java.util.List;
import java.util.Map;

@Service
public class DeviceServiceImpl extends ServiceImpl<DeviceMapper, Device> implements DeviceService {

    @Override
    public List<Device> findByNameLike(String name) {
        LambdaQueryWrapper<Device> wrapper = new LambdaQueryWrapper<>();
        wrapper.like(Device::getDeviceName, name);
        return list(wrapper);
    }

    @Override
    public List<Device> findOnlineDevices() {
        LambdaQueryWrapper<Device> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(Device::getStatus, 1)
               .orderByDesc(Device::getUpdateTime);
        return list(wrapper);
    }

    @Override
    public boolean updateStatus(Integer id, Integer status) {
        LambdaUpdateWrapper<Device> wrapper = new LambdaUpdateWrapper<>();
        wrapper.eq(Device::getId, id)
               .set(Device::getStatus, status);
        if (status == 1) {
            wrapper.set(Device::getLastOnlineTime, LocalDateTime.now());
        }
        return update(wrapper);
    }

    public List<Device> findByTypeId(Integer typeId) {
        LambdaQueryWrapper<Device> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(Device::getTypeId, typeId);
        return list(wrapper);
    }

    public List<Map<String, Object>> countByStatus() {
        return baseMapper.countByStatus();
    }
}
```

> **💡 说明**：
> - `wrapper.eq(Device::getStatus, 1)` → 生成 `WHERE status = 1`
> - `wrapper.like(Device::getDeviceName, name)` → 生成 `WHERE device_name LIKE '%name%'`
> - `wrapper.orderByDesc(Device::getUpdateTime)` → 生成 `ORDER BY update_time DESC`
> - `wrapper.set(Device::getStatus, status)` → 生成 `SET status = ?`
> - `updateStatus` 方法中，当状态设为在线(1)时，同时更新 `lastOnlineTime`，这是业务逻辑，放在 Service 层最合适

```java
public Result<Page<Device>> listByPage(
        @RequestParam(defaultValue = "1") Integer current,
        @RequestParam(defaultValue = "10") Integer size,
        @RequestParam(required = false) Integer status,
        @RequestParam(required = false) String name) {

}
```

### 📚 概念→代码映射：@Transactional → 多表操作

回顾第二周学习的 ACID 概念，`@Transactional` 注解可以确保多个数据库操作的原子性：

```java
@Service
public class DeviceServiceImpl extends ServiceImpl<DeviceMapper, Device> implements DeviceService {

    @Autowired
    private DeviceDataService deviceDataService;

    @Transactional(rollbackFor = Exception.class)
    public Device addDeviceWithData(Device device, DeviceData initialData) {
        save(device);
        initialData.setDeviceId(device.getId());
        deviceDataService.save(initialData);
        return device;
    }
}
```

**执行流程：**

```
1. 开启事务
2. INSERT INTO devices (...) VALUES (...)     → 成功，device.getId() 获取自增主键
3. INSERT INTO device_data (...) VALUES (...)  → 如果失败
4. 事务回滚 → 第2步的 INSERT 也会被撤销
5. 如果第3步也成功 → 事务提交
```

> **💡 说明**：`rollbackFor = Exception.class` 表示任何异常都触发回滚。默认情况下，Spring 只在 `RuntimeException` 和 `Error` 时回滚，加上这个参数可以确保受检异常也触发回滚。

### 📚 知识准备：什么是 CORS？

**同源策略**是浏览器的安全机制，要求网页只能请求与自身同源（相同协议+域名+端口）的资源。

| URL A | URL B | 是否同源 | 原因 |
|-------|-------|---------|------|
| `http://localhost:3000` | `http://localhost:8080` | ❌ | 端口不同 |
| `http://example.com` | `https://example.com` | ❌ | 协议不同 |
| `http://localhost:8080` | `http://localhost:8080/api` | ✅ | 同源，路径不同不影响 |

当前后端运行在 `localhost:8080`，未来前端（第8周）运行在 `localhost:3000`，属于跨域请求，浏览器会阻止。

**CORS（Cross-Origin Resource Sharing）** 是解决跨域的标准方案。服务端在响应头中添加 `Access-Control-Allow-Origin` 等字段，告诉浏览器"允许这个源访问我的资源"。

### 任务一：添加 CORS 跨域配置

**▶ 任务要求**

- 创建 `CorsConfig` 配置类
- 允许 `localhost` 的所有端口访问
- 允许所有常用的 HTTP 方法和请求头

**📁 文件路径：src/main/java/com/example/platform/config/CorsConfig.java**

**📝 参考代码：**

```java
package com.example.platform.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.cors.CorsConfiguration;
import org.springframework.web.cors.UrlBasedCorsConfigurationSource;
import org.springframework.web.filter.CorsFilter;

@Configuration
public class CorsConfig {

    @Bean
    public CorsFilter corsFilter() {
        CorsConfiguration config = new CorsConfiguration();
        config.addAllowedOriginPattern("http://localhost:*");
        config.addAllowedOriginPattern("http://127.0.0.1:*");
        config.addAllowedMethod("*");
        config.addAllowedHeader("*");
        config.setAllowCredentials(true);
        config.setMaxAge(3600L);

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);
        return new CorsFilter(source);
    }
}
```

> **💡 说明**：
> - `addAllowedOriginPattern("http://localhost:*")` 允许 localhost 的所有端口访问
> - `addAllowedMethod("*")` 允许所有 HTTP 方法（GET、POST、PUT、DELETE 等）
> - `addAllowedHeader("*")` 允许所有请求头
> - `setAllowCredentials(true)` 允许携带 Cookie（前后端分离项目通常需要）
> - `setMaxAge(3600L)` 预检请求缓存1小时，减少 OPTIONS 请求次数
> - `registerCorsConfiguration("/**", config)` 对所有路径生效

> **⚠️ 注意**：`addAllowedOrigin("*")` 和 `setAllowCredentials(true)` 不能同时使用，浏览器会拒绝。如果需要携带 Cookie，必须使用 `addAllowedOriginPattern` 指定具体域名。

# 第四章 避坑指南——设备管理模块开发中最容易犯的8个错误

## 错误1：忘记加 @Service 注解

| 项目 | 内容 |
|------|------|
| **症状** | Controller 注入 Service 时报 `NoSuchBeanDefinitionException` |
| **原因** | ServiceImpl 类没有 `@Service` 注解，Spring 无法将其注册为 Bean |
| **解决方案** | 在每个 ServiceImpl 类上添加 `@Service` 注解 |

```java
// ❌ 错误：缺少 @Service
public class AlertServiceImpl extends ServiceImpl<AlertMapper, Alert> implements AlertService {
}

// ✅ 正确：添加 @Service
@Service
public class AlertServiceImpl extends ServiceImpl<AlertMapper, Alert> implements AlertService {
}
```

## 错误2：application.yml 包名写错

| 项目 | 内容 |
|------|------|
| **症状** | MyBatis-Plus 报 `Invalid bound statement` 或找不到实体类别名 |
| **原因** | `type-aliases-package` 配置的包名与实际包路径不一致 |
| **解决方案** | 确保配置中的包名与 `@SpringBootApplication` 所在包一致 |

```yaml
# ❌ 错误：包名不匹配
mybatis-plus:
  type-aliases-package: com.iot.platform.entity

# ✅ 正确：与实际包路径一致
mybatis-plus:
  type-aliases-package: com.example.platform.entity
```

## 错误3：分页插件未启用

| 项目 | 内容 |
|------|------|
| **症状** | `Page.getTotal()` 返回0，分页查询返回全部数据 |
| **原因** | `MybatisPlusConfig` 被注释，`PaginationInnerInterceptor` 未注册 |
| **解决方案** | 取消 `MybatisPlusConfig` 中的注释，确保 `@Configuration` 和 `@Bean` 注解存在 |

```java
// ❌ 错误：整个配置类被注释
// @Configuration
// public class MybatisPlusConfig { ... }

// ✅ 正确：取消注释
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

## 错误4：@GetMapping 路径冲突

| 项目 | 内容 |
|------|------|
| **症状** | 访问 `/devices/online` 返回404，或被 `/{id}` 拦截 |
| **原因** | `@GetMapping("/{id}")` 和 `@GetMapping("/online")` 路径冲突，Spring 把 `online` 当作 id |
| **解决方案** | 将固定路径的方法放在路径变量方法之前；或使用不同的 URL 前缀 |

```java
// ✅ 正确：固定路径在前，路径变量在后
@GetMapping("/online")
public Result<List<Device>> onlineList() { ... }

@GetMapping("/{id}")
public Result<Device> getById(@PathVariable Integer id) { ... }
```

## 错误5：POST 请求缺少 Content-Type

| 项目 | 内容 |
|------|------|
| **症状** | POST 请求返回 `415 Unsupported Media Type` |
| **原因** | 请求头未设置 `Content-Type: application/json` |
| **解决方案** | 在 Postman 或前端代码中添加请求头 |

```bash
# ✅ 正确：添加 Content-Type
curl -X POST http://localhost:8080/api/devices \
  -H "Content-Type: application/json" \
  -d '{"deviceName":"测试","deviceCode":"TEST-001"}'
```

## 错误6：@Valid 校验不生效

| 项目 | 内容 |
|------|------|
| **症状** | 传入空参数但校验注解没有拦截，直接执行到 Service 层 |
| **原因** | Controller 方法参数上忘记加 `@Valid` 注解 |
| **解决方案** | 在 `@RequestBody` 前添加 `@Valid` |

```java
// ❌ 错误：缺少 @Valid
public Result<Void> save(@RequestBody Device device) { ... }

// ✅ 正确：添加 @Valid
public Result<Void> save(@Valid @RequestBody Device device) { ... }
```

## 错误7：MetaObjectHandler 不生效

| 项目 | 内容 |
|------|------|
| **症状** | 新增数据后 `createTime` 为 null，但没有任何报错 |
| **原因** | 忘记在 Handler 类上添加 `@Component` 注解，或实体字段未配置 `fill` 属性 |
| **解决方案** | 确保两处都正确配置 |

```java
// ✅ 1. Handler 类必须有 @Component
@Component
public class MyMetaObjectHandler implements MetaObjectHandler { ... }

// ✅ 2. 实体字段必须配置 fill
@TableField(value = "create_time", fill = FieldFill.INSERT)
private LocalDateTime createTime;
```

## 错误8：CORS 配置与 Credentials 冲突

| 项目 | 内容 |
|------|------|
| **症状** | 浏览器控制台报错 `The value of the 'Access-Control-Allow-Origin' header in the response must not be the wildcard '*' when the request's credentials mode is include` |
| **原因** | 同时使用了 `addAllowedOrigin("*")` 和 `setAllowCredentials(true)` |
| **解决方案** | 使用 `addAllowedOriginPattern` 替代 `addAllowedOrigin("*")` |

```java
// ❌ 错误：通配符 + Credentials 冲突
config.addAllowedOrigin("*");
config.setAllowCredentials(true);

// ✅ 正确：使用 OriginPattern
config.addAllowedOriginPattern("http://localhost:*");
config.setAllowCredentials(true);
```
