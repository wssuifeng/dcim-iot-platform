# Git 常用操作与指令速查表（团队协作增强版）
## 📌 核心概念（工作区域）
1. **工作区**：你当前正在编辑的文件目录。
2. **暂存区**：`git add` 后，文件保存的地方，属于下一次提交的快照。
3. **本地仓库**：`git commit` 后，快照永久保存在本地的版本库。
4. **远程仓库**：托管代码的服务器（如 GitHub, GitLab）。
---
## 1. 初始配置
首次安装 Git 或在新环境需要配置用户信息。
| 操作         | 指令                                                 | 说明                        |
| :----------- | :--------------------------------------------------- | :-------------------------- |
| 设置用户名   | `git config --global user.name "Your Name"`          | 全局配置提交者姓名          |
| 设置邮箱     | `git config --global user.email "email@example.com"` | 全局配置提交者邮箱          |
| 查看配置信息 | `git config --list`                                  | 查看当前所有配置项          |
| 保存密码     | `git config --global credential.helper store`        | 避免每次 push/pull 都输密码 |

## 2. 创建与初始化
| 操作         | 指令                               | 说明                                |
| :----------- | :--------------------------------- | :---------------------------------- |
| 初始化仓库   | `git init`                         | 在当前目录创建一个新的本地 Git 仓库 |
| 克隆远程仓库 | `git clone <url>`                  | 下载远程仓库到本地                  |
| 克隆指定分支 | `git clone -b <branch-name> <url>` | 只克隆远程的指定分支                |

## 3. 基本暂存与提交
| 操作               | 指令                          | 说明                                             |
| :----------------- | :---------------------------- | :----------------------------------------------- |
| 查看状态           | `git status`                  | 查看工作区和暂存区的状态（红=未暂存，绿=已暂存） |
| 查看简略状态       | `git status -s`               | 输出更紧凑的状态信息                             |
| 添加单个文件       | `git add <file>`              | 将指定文件添加到暂存区                           |
| 添加所有文件       | `git add .`                   | 将当前目录下所有修改添加到暂存区                 |
| 添加所有文件(推荐) | `git add -A`                  | 添加工作区所有改动（新增、修改、删除）           |
| 提交暂存区         | `git commit -m "message"`     | 提交暂存区到本地仓库，并附带提交信息             |
| 跳过暂存直接提交   | `git commit -am "message"`    | 将已跟踪文件的修改提交（未跟踪文件无效）         |
| 修改上次提交       | `git commit --amend -m "msg"` | 用新提交替换上次提交（常用于写错信息或漏文件）   |

## 4. 远程仓库同步
> 🌟 **协作场景：团队成员更新了远程仓库，我需要把最新代码拉下来同步**
> ```bash
> # 1. 拉取远程最新的内容（不合并，先看看）
> git fetch origin
> # 2. 确认没问题后，拉取并合并到当前分支
> git pull origin main
> ```
| 操作             | 指令                                  | 说明                                             |
| :--------------- | :------------------------------------ | :----------------------------------------------- |
| 查看远程仓库     | `git remote -v`                       | 查看关联的远程仓库地址                           |
| 添加远程仓库     | `git remote add origin <url>`         | 关联一个远程仓库，命名为 origin                  |
| 修改远程仓库地址 | `git remote set-url origin <new-url>` | 更换远程仓库 URL                                 |
| 拉取远程更新     | `git fetch origin`                    | 拉取远程最新内容，但不合并到当前分支             |
| 拉取并合并       | `git pull origin <branch>`            | 拉取远程分支并合并到当前分支 (`fetch` + `merge`) |
| 推送到远程       | `git push origin <branch>`            | 将本地分支推送到远程对应分支                     |
| 首次推送并关联   | `git push -u origin <branch>`         | 推送并设置上游分支（后续直接 `git push` 即可）   |
| 强制推送         | `git push -f origin <branch>`         | 强制覆盖远程分支（⚠️ 危险操作，团队协作慎用）     |

## 5. 分支操作
> 🌟 **协作场景 1：接到新需求，需要从主分支拉出一条功能分支开发**
> ```bash
> # 1. 切到主分支并拉取最新代码
> git checkout main
> git pull origin main
> # 2. 创建并切换到新功能分支
> git switch -c feature/user-login
> # 3. 开发完后推送到远程建立分支
> git push -u origin feature/user-login
> ```
> 🌟 **协作场景 2：功能开发完成，提 MR/PR 前先同步主分支的最新代码，避免冲突**
> ```bash
> # 1. 在当前功能分支，拉取主分支的最新代码并合并进来
> git fetch origin
> git merge origin/main
> # （如果有冲突，解决冲突后 git add . && git commit）
> # 2. 推送到远程，准备提 Merge Request
> git push origin feature/user-login
> ```
| 操作             | 指令                                | 说明                                                   |
| :--------------- | :---------------------------------- | :----------------------------------------------------- |
| 查看本地分支     | `git branch`                        | 列出所有本地分支，`*` 表示当前分支                     |
| 查看所有分支     | `git branch -a`                     | 列出本地和远程所有分支                                 |
| 创建新分支       | `git branch <branch-name>`          | 基于当前分支创建新分支（停留在原分支）                 |
| 切换分支         | `git checkout <branch-name>`        | 切换到指定分支                                         |
| 新版切换分支     | `git switch <branch-name>`          | Git 2.23+ 推荐，语义更清晰                             |
| 创建并切换       | `git checkout -b <branch-name>`     | 创建新分支并立即切换过去                               |
| 新版创建并切换   | `git switch -c <branch-name>`       | Git 2.23+ 推荐写法                                     |
| 合并分支         | `git merge <branch-name>`           | 将指定分支合并到当前分支                               |
| 变基合并         | `git rebase <branch-name>`          | 将当前分支的提交重新应用到目标分支之上（保持线性历史） |
| 删除本地分支     | `git branch -d <branch-name>`       | 删除已合并的本地分支                                   |
| 强制删除本地分支 | `git branch -D <branch-name>`       | 强制删除未合并的本地分支                               |
| 删除远程分支     | `git push origin --delete <branch>` | 删除远程服务器上的分支                                 |

## 6. 查看历史与差异
| 操作             | 指令                                   | 说明                                                 |
| :--------------- | :------------------------------------- | :--------------------------------------------------- |
| 查看提交历史     | `git log`                              | 显示完整的提交历史记录                               |
| 简略查看历史     | `git log --oneline`                    | 每次提交显示为一行（常用于查看版本号）               |

| 查看工作区差异   | `git diff`                             | 查看工作区与暂存区的差异（尚未 `add` 的修改）        |
| 查看暂存区差异   | `git diff --staged`                    | 查看暂存区与本地仓库的差异（已 `add` 但未 `commit`） |
| 查看某次提交详情 | `git show <commit-id>`                 | 显示某次提交的元数据和具体改动                       |

## 7. 撤销与回退
> 🌟 **协作场景：刚推送到远程的代码导致 CI/CD 报错，需要安全撤回（不影响同事已拉取的代码）**
> ```bash
> # 千万不要用 reset --hard 后强行 push，这会让同事的代码丢失！
> # 1. 找到要撤销的 commit id
> git log --oneline
> # 2. 生成一个反向提交来抵消它（安全撤回）
> git revert <commit-id>
> # 3. 推送到远程
> git push origin main
> ```
| 操作           | 指令                           | 说明                                             |
| :------------- | :----------------------------- | :----------------------------------------------- |
| 撤销工作区修改 | `git restore <file>`           | 丢弃工作区的修改，回到暂存区或本地仓库的状态     |
| 取消暂存       | `git restore --staged <file>`  | 将文件从暂存区撤回工作区（不影响文件内容）       |
| 回退到上一版本 | `git reset --soft HEAD^`       | 回退提交，但保留修改在暂存区（极安全）           |
| 回退到上一版本 | `git reset --mixed HEAD^`      | 回退提交，保留修改在工作区（默认模式）           |
| 回退到上一版本 | `git reset --hard HEAD^`       | 彻底回退，丢弃所有修改（⚠️ 代码会丢失）           |
| 回退到指定版本 | `git reset --hard <commit-id>` | 彻底回退到指定版本                               |
| 撤销某次提交   | `git revert <commit-id>`       | 生成一个新提交来抵消指定提交（安全，不影响历史） |
> **💡 `reset` 与 `revert` 的区别：** `reset` 是“时光倒流”，仅限本地使用；`revert` 是“反向操作”，产生新提交保留历史，适合已推送到远程的代码撤回。

## 8. 暂存工作
> 🌟 **协作场景：正在 feature 分支写代码写了一半，突然被叫去修 main 分支的紧急 Bug**
> ```bash
> # 1. 将写了一半的代码暂存起来
> git stash save "写了一半的登录功能"
> # 2. 切去 main 分支修 Bug
> git checkout main
> # ... 修 Bug，提交推送 ...
> # 3. 切回原分支，恢复刚才的进度继续写
> git checkout feature
> git stash pop
> ```
| 操作           | 指令                        | 说明                                |
| :------------- | :-------------------------- | :---------------------------------- |
| 保存当前进度   | `git stash`                 | 将工作区和暂存区的修改保存到栈中    |
| 保存并添加备注 | `git stash save "message"`  | 同上，附带说明信息（推荐）          |
| 查看暂存列表   | `git stash list`            | 查看所有 stash 记录                 |
| 恢复最近暂存   | `git stash pop`             | 恢复最近一次 stash 并将其从栈中删除 |
| 恢复指定暂存   | `git stash apply stash@{0}` | 恢复指定 stash，但不从栈中删除      |
| 删除暂存       | `git stash drop stash@{0}`  | 删除指定 stash                      |
| 清空所有暂存   | `git stash clear`           | 删除所有 stash 记录                 |

## 9. 代码整理（高级协作技巧）
> 🌟 **协作场景：提 MR/PR 前，发现自己在这个分支上有 10 几个无意义的提交（如：fix, fix again, 修bug），想让提交历史变干净**
> ```bash
> # 1. 查看提交历史，决定要把哪几个 commit 合并
> git log --oneline
> # 2. 开始交互式变基（例如合并最近 3 个提交）
> git rebase -i HEAD~3
> # 3. 在弹出的编辑器中，把第 2、3 行的 pick 改为 squash（表示压缩到上一个提交）
> # 4. 保存后，在下一个弹窗中编辑合并后的 commit message
> # 5. 强行推送到远程覆盖原来凌乱的提交记录
> git push -f origin feature/user-login
> ```
| 操作       | 指令                    | 说明                                        |
| :--------- | :---------------------- | :------------------------------------------ |
| 交互式变基 | `git rebase -i HEAD~n`  | 整理最近 n 次提交（可合并、修改、删除提交） |
| 继续变基   | `git rebase --continue` | 解决冲突后，继续执行变基操作                |
| 放弃变基   | `git rebase --abort`    | 撤销本次变基操作，回到变基前状态            |

## 10. 标签管理
通常用于标记发布版本（如 v1.0.0）。
| 操作             | 指令                                 | 说明                                       |
| :--------------- | :----------------------------------- | :----------------------------------------- |
| 查看所有标签     | `git tag`                            | 列出所有标签                               |
| 创建轻量标签     | `git tag <tagname>`                  | 创建一个轻量标签                           |
| 创建附注标签     | `git tag -a <tagname> -m "msg"`      | 创建附注标签（包含作者、日期、信息，推荐） |
| 给历史提交打标签 | `git tag -a <tagname> <commit-id>`   | 为过去的某次提交补打标签                   |
| 推送单个标签     | `git push origin <tagname>`          | 将本地标签推送到远程                       |
| 推送所有标签     | `git push origin --tags`             | 将本地所有未推送的标签推送到远程           |
| 删除本地标签     | `git tag -d <tagname>`               | 删除本地标签                               |
| 删除远程标签     | `git push origin --delete <tagname>` | 删除远程服务器上的标签                     |

## 11. 救援与日常清理
| 操作               | 指令            | 说明                                                     |
| :----------------- | :-------------- | :------------------------------------------------------- |
| 找回丢失的提交     | `git reflog`    | 记录所有 HEAD 移动记录（误操作 `reset --hard` 后的救星） |
| 清理未跟踪文件     | `git clean -n`  | 预览哪些未跟踪文件会被删除（干跑模式）                   |
| 强制清理未跟踪文件 | `git clean -fd` | 删除未跟踪的文件和目录（⚠️ 不可恢复，慎用）               |
