# 第一章 概念引入——为什么要先搭骨架？

## 1.1 什么是项目骨架？

项目骨架（Project Skeleton）是指一个项目的基础结构，包括：

- **目录结构**：标准的包分层（entity、mapper、service、controller）
- **配置文件**：数据库连接、框架配置、日志配置
- **依赖管理**：pom.xml中的所有依赖声明
- **基础代码**：通用的工具类、配置类、实体类

> **💡 类比理解**：项目骨架就像盖房子的地基和框架。地基打好了，后面砌墙、装修（写业务代码）才能顺利进行。

## 1.2 为什么要先搭骨架？

很多初学者喜欢直接上手写业务代码，结果遇到各种问题：

| 问题 | 直接上手写代码 | 先搭骨架再开发 |
|-----|--------------|--------------|
| 配置错误 | 写到一半发现配置不对，推倒重来 | 配置先验证通过，后续无忧 |
| 依赖冲突 | 缺少依赖或版本冲突，调试半天 | 依赖先测试好，版本统一管理 |
| 结构混乱 | 代码到处放，后期难以维护 | 标准分层结构，清晰明了 |
| 无法回滚 | 出问题不知道哪里错了 | Git管理，随时回退 |

> **⚠️ 警告**：不要跳过骨架搭建直接写业务代码！这就像不画图纸直接盖楼，后期一定会出问题。

## 1.3 MyBatis vs MyBatis-Plus

在第三周，我们学习了原生MyBatis。本周开始使用MyBatis-Plus，它有什么优势？

| 对比项 | MyBatis | MyBatis-Plus |
|-------|---------|-------------|
| CRUD代码 | 需要手写全部SQL | 单表CRUD自动生成 |
| 分页查询 | 需要手写分页SQL | 内置分页插件 |
| 条件构造 | 需要手写动态SQL | Wrapper链式调用 |
| 代码生成 | 无 | 支持代码生成器 |
| 学习成本 | 较低 | 略高（需要学习Wrapper） |

> **💡 说明**：MyBatis-Plus是MyBatis的增强工具，**不改变**MyBatis原有功能，只是让单表操作更简单。复杂SQL仍然可以使用XML方式编写。

### 任务一：绘制物联网平台数据库ER图（30分钟）

**▶ 任务要求**

- 理解物联网平台的核心业务实体
- 分析实体之间的关系（一对多、多对多）
- 绘制ER图，标注主键、外键
- 理解为什么需要设备类型表

**📝 设计思路**

物联网设备管理平台的核心实体：

| 实体 | 说明 | 主要属性 |
|-----|------|---------|
| 设备类型 | 设备的分类信息 | 类型ID、类型名称、描述 |
| 设备 | 具体的设备实例 | 设备ID、名称、类型、状态、位置 |
| 设备数据 | 设备采集的数据 | 数据ID、设备ID、数据值、采集时间 |
| 告警记录 | 设备产生的告警 | 告警ID、设备ID、告警类型、级别、时间 |

**ER图关系说明：**

```
┌─────────────┐       ┌─────────────┐
│ device_types│       │   devices   │
├─────────────┤       ├─────────────┤
│ id (PK)     │◄──────│ type_id(FK) │
│ type_name   │  1:N  │ id (PK)     │
│ description │       │ device_name │
└─────────────┘       │ status      │
                      └─────────────┘
                            │
                            │ 1:N
                            ▼
                      ┌─────────────┐
                      │ device_data │
                      ├─────────────┤
                      │ id (PK)     │
                      │ device_id(FK)│
                      │ data_value  │
                      │ collect_time│
                      └─────────────┘
                            ▲
                            │
                      ┌─────────────┐
                      │   alerts    │
                      ├─────────────┤
                      │ id (PK)     │
                      │ device_id(FK)│
                      │ alert_type  │
                      │ alert_level │
                      └─────────────┘
```

> **💡 设计说明**：设备类型与设备是1:N关系（一个类型对应多个设备）；设备与设备数据是1:N关系（一个设备有多条采集数据）；设备与告警也是1:N关系。

### 任务二：编写完整DDL建表脚本（50分钟）

**▶ 任务要求**

- 创建数据库 iot_device_db
- 创建4张核心表：device_types、devices、device_data、alerts
- 设置主键、外键、索引
- 添加字段注释
- 使用utf8mb4字符集

**📁 文件路径：sql/design.sql**

**📝 参考代码：**

```sql
-- ==================== 创建数据库 ====================
CREATE DATABASE IF NOT EXISTS iot_device_db 
DEFAULT CHARACTER SET utf8mb4 
DEFAULT COLLATE utf8mb4_unicode_ci;

USE iot_device_db;

-- ==================== 1. 设备类型表 ====================
DROP TABLE IF EXISTS device_types;
CREATE TABLE device_types (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '类型ID',
    type_name VARCHAR(30) NOT NULL UNIQUE COMMENT '类型名称',
    type_code VARCHAR(20) UNIQUE COMMENT '类型编码',
    description VARCHAR(200) COMMENT '类型描述',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备类型表';

-- ==================== 2. 设备信息表 ====================
DROP TABLE IF EXISTS devices;
CREATE TABLE devices (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '设备ID',
    device_name VARCHAR(50) NOT NULL COMMENT '设备名称',
    device_code VARCHAR(30) UNIQUE COMMENT '设备编码',
    type_id INT COMMENT '类型ID',
    status TINYINT DEFAULT 0 COMMENT '状态：0离线 1在线 2故障',
    location VARCHAR(100) COMMENT '设备位置',
    ip_address VARCHAR(50) COMMENT 'IP地址',
    last_online_time DATETIME COMMENT '最后在线时间',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    -- 外键约束
    CONSTRAINT fk_device_type FOREIGN KEY (type_id) REFERENCES device_types(id),
    -- 索引
    INDEX idx_device_name (device_name),
    INDEX idx_status (status),
    INDEX idx_type_id (type_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备信息表';

-- ==================== 3. 设备数据表 ====================
DROP TABLE IF EXISTS device_data;
CREATE TABLE device_data (
    id BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '数据ID',
    device_id INT NOT NULL COMMENT '设备ID',
    data_value DECIMAL(10,2) COMMENT '数据值',
    data_unit VARCHAR(20) COMMENT '数据单位',
    collect_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '采集时间',
    -- 外键约束
    CONSTRAINT fk_data_device FOREIGN KEY (device_id) REFERENCES devices(id),
    -- 索引
    INDEX idx_device_id (device_id),
    INDEX idx_collect_time (collect_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='设备数据表';

-- ==================== 4. 告警记录表 ====================
DROP TABLE IF EXISTS alerts;
CREATE TABLE alerts (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '告警ID',
    device_id INT NOT NULL COMMENT '设备ID',
    alert_type VARCHAR(30) COMMENT '告警类型',
    alert_level TINYINT DEFAULT 1 COMMENT '告警级别：1一般 2严重 3紧急',
    alert_message VARCHAR(500) COMMENT '告警信息',
    is_handled TINYINT DEFAULT 0 COMMENT '是否处理：0未处理 1已处理',
    handle_time DATETIME COMMENT '处理时间',
    handle_user VARCHAR(50) COMMENT '处理人',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    -- 外键约束
    CONSTRAINT fk_alert_device FOREIGN KEY (device_id) REFERENCES devices(id),
    -- 索引
    INDEX idx_device_id (device_id),
    INDEX idx_alert_level (alert_level),
    INDEX idx_is_handled (is_handled)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='告警记录表';
```

> **💡 说明**：
> - `ENGINE=InnoDB`：使用InnoDB存储引擎，支持事务和外键
> - `DEFAULT CHARSET=utf8mb4`：使用utf8mb4字符集，支持emoji
> - `COMMENT`：字段注释，方便后续维护
> - `INDEX`：索引，加速查询

### 任务四：编写常用查询验证脚本（30分钟）

**▶ 任务要求**

- 查询设备在线率统计
- 查询最近24小时数据趋势
- 查询未处理告警列表
- 验证外键关系是否正确

**📁 文件路径：sql/verify.sql**

**📝 参考代码：**

```sql
-- ==================== 1. 验证数据量 ====================
SELECT '设备类型数量' AS 统计项, COUNT(*) AS 数量 FROM device_types
UNION ALL
SELECT '设备数量', COUNT(*) FROM devices
UNION ALL
SELECT '数据记录数量', COUNT(*) FROM device_data
UNION ALL
SELECT '告警记录数量', COUNT(*) FROM alerts;

-- ==================== 2. 设备在线率统计 ====================
SELECT 
    dt.type_name AS '设备类型',
    COUNT(d.id) AS '设备总数',
    SUM(CASE WHEN d.status = 1 THEN 1 ELSE 0 END) AS '在线数量',
    CONCAT(ROUND(SUM(CASE WHEN d.status = 1 THEN 1 ELSE 0 END) / COUNT(d.id) * 100, 1), '%') AS '在线率'
FROM device_types dt
LEFT JOIN devices d ON dt.id = d.type_id
GROUP BY dt.id, dt.type_name;

-- ==================== 3. 最近24小时数据趋势 ====================
SELECT 
    d.device_name AS '设备名称',
    COUNT(dd.id) AS '数据条数',
    MIN(dd.data_value) AS '最小值',
    MAX(dd.data_value) AS '最大值',
    ROUND(AVG(dd.data_value), 2) AS '平均值'
FROM devices d
JOIN device_data dd ON d.id = dd.device_id
WHERE dd.collect_time >= DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY d.id, d.device_name
ORDER BY 数据条数 DESC;

-- ==================== 4. 未处理告警列表 ====================
SELECT 
    a.id,
    d.device_name AS '设备名称',
    a.alert_type AS '告警类型',
    CASE a.alert_level 
        WHEN 1 THEN '一般' 
        WHEN 2 THEN '严重' 
        WHEN 3 THEN '紧急' 
    END AS '告警级别',
    a.alert_message AS '告警信息',
    a.create_time AS '告警时间'
FROM alerts a
JOIN devices d ON a.device_id = d.id
WHERE a.is_handled = 0
ORDER BY a.alert_level DESC, a.create_time DESC;

-- ==================== 5. 验证外键关系 ====================
-- 查询每个设备的类型信息（验证一对多）
SELECT 
    d.device_name,
    dt.type_name,
    dt.description
FROM devices d
LEFT JOIN device_types dt ON d.type_id = dt.id
LIMIT 5;
```

### 任务一：创建Device实体类（30分钟）

**▶ 任务要求**

- 创建Device实体类，对应devices表
- 使用@TableName注解指定表名
- 使用@TableId注解指定主键
- 使用@TableField注解处理字段映射
- 使用Lombok简化代码

**📁 文件路径：src/main/java/com/iot/platform/entity/Device.java**

**📝 参考代码：**

```java
package com.iot.platform.entity;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;
import java.io.Serializable;
import java.time.LocalDateTime;

/**
 * 设备实体类
 * 对应数据库表：devices
 */
@Data
@TableName("devices")
public class Device implements Serializable {
    
    /**
     * 设备ID（主键，自增）
     */
    @TableId(value = "id", type = IdType.AUTO)
    private Integer id;
    
    /**
     * 设备名称
     */
    @TableField("device_name")
    private String deviceName;
    
    /**
     * 设备编码
     */
    @TableField("device_code")
    private String deviceCode;
    
    /**
     * 类型ID
     */
    @TableField("type_id")
    private Integer typeId;
    
    /**
     * 状态：0离线 1在线 2故障
     */
    private Integer status;
    
    /**
     * 设备位置
     */
    private String location;
    
    /**
     * IP地址
     */
    @TableField("ip_address")
    private String ipAddress;
    
    /**
     * 最后在线时间
     */
    @TableField("last_online_time")
    private LocalDateTime lastOnlineTime;
    
    /**
     * 创建时间
     */
    @TableField(value = "create_time", fill = FieldFill.INSERT)
    private LocalDateTime createTime;
    
    /**
     * 更新时间
     */
    @TableField(value = "update_time", fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

> **💡 说明**：
> - `@TableName`：指定对应的数据库表名
> - `@TableId`：指定主键，`IdType.AUTO`表示自增
> - `@TableField`：指定字段映射，`fill = FieldFill.INSERT`表示插入时自动填充

**📝 参考代码：**

```java
package com.iot.platform.mapper;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;
import com.iot.platform.entity.Device;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;
import org.apache.ibatis.annotations.Select;

import java.util.List;

/**
 * 设备Mapper接口
 * 继承BaseMapper后，自动拥有以下方法：
 * - insert(entity)：插入
 * - deleteById(id)：根据ID删除
 * - updateById(entity)：根据ID更新
 * - selectById(id)：根据ID查询
 * - selectList(wrapper)：条件查询列表
 * - selectPage(page, wrapper)：分页查询
 */
@Mapper
public interface DeviceMapper extends BaseMapper<Device> {
    
    /**
     * 根据设备名称模糊查询
     * @param name 设备名称
     * @return 设备列表
     */
    @Select("SELECT * FROM devices WHERE device_name LIKE CONCAT('%', #{name}, '%')")
    List<Device> findByNameLike(@Param("name") String name);
    
    /**
     * 统计各状态的设备数量
     * @return 统计结果
     */
    @Select("SELECT status, COUNT(*) as count FROM devices GROUP BY status")
    List<java.util.Map<String, Object>> countByStatus();
}
```

> **💡 BaseMapper提供的常用方法：**

| 方法 | 说明 |
|-----|------|
| `insert(T entity)` | 插入一条记录 |
| `deleteById(Serializable id)` | 根据ID删除 |
| `delete(Wrapper<T> wrapper)` | 根据条件删除 |
| `updateById(T entity)` | 根据ID更新 |
| `update(T entity, Wrapper<T> wrapper)` | 根据条件更新 |
| `selectById(Serializable id)` | 根据ID查询 |
| `selectBatchIds(Collection ids)` | 根据ID批量查询 |
| `selectList(Wrapper<T> wrapper)` | 条件查询列表 |
| `selectPage(Page<T> page, Wrapper<T> wrapper)` | 分页查询 |

**📝 参考代码：**

```java
package com.iot.platform.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.conditions.update.LambdaUpdateWrapper;
import com.baomidou.mybatisplus.extension.service.impl.ServiceImpl;
import com.iot.platform.entity.Device;
import com.iot.platform.mapper.DeviceMapper;
import com.iot.platform.service.DeviceService;
import org.springframework.stereotype.Service;

import java.util.List;

/**
 * 设备服务实现类
 * 继承ServiceImpl后，自动拥有BaseMapper的所有方法
 */
@Service
public class DeviceServiceImpl extends ServiceImpl<DeviceMapper, Device> implements DeviceService {
    
    @Override
    public List<Device> findByNameLike(String name) {
        return baseMapper.findByNameLike(name);
    }
    
    @Override
    public List<Device> findOnlineDevices() {
        // 使用LambdaQueryWrapper构建查询条件
        LambdaQueryWrapper<Device> wrapper = new LambdaQueryWrapper<>();
        wrapper.eq(Device::getStatus, 1);  // status = 1 表示在线
        return list(wrapper);
    }
    
    @Override
    public boolean updateStatus(Integer id, Integer status) {
        // 使用LambdaUpdateWrapper构建更新条件
        LambdaUpdateWrapper<Device> wrapper = new LambdaUpdateWrapper<>();
        wrapper.eq(Device::getId, id)
               .set(Device::getStatus, status);
        return update(wrapper);
    }
}
```

> **💡 说明**：
> - `IService`和`ServiceImpl`是MyBatis-Plus提供的服务层封装
> - 继承后自动拥有CRUD方法，无需手动调用Mapper
> - `LambdaQueryWrapper`用于构建查询条件，类型安全

```java
package com.iot.platform.controller;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.iot.platform.common.Result;
import com.iot.platform.entity.Device;
import com.iot.platform.service.DeviceService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

/**
 * 设备控制器
 */
@RestController
@RequestMapping("/devices")
public class DeviceController {
    
    @Autowired
    private DeviceService deviceService;
    
    /**
     * 查询设备列表（分页）
     * GET /api/devices?page=1&size=10
     */
    @GetMapping
    public Result<Page<Device>> list(
            @RequestParam(defaultValue = "1") Integer page,
            @RequestParam(defaultValue = "10") Integer size) {
        Page<Device> pageParam = new Page<>(page, size);
        Page<Device> result = deviceService.page(pageParam);
        return Result.success(result);
    }
    
    /**
     * 根据ID查询设备
     * GET /api/devices/{id}
     */
    @GetMapping("/{id}")
    public Result<Device> getById(@PathVariable Integer id) {
        Device device = deviceService.getById(id);
        if (device == null) {
            return Result.error("设备不存在");
        }
        return Result.success(device);
    }
    
    /**
     * 添加设备
     * POST /api/devices
     */
    @PostMapping
    public Result<Device> add(@RequestBody Device device) {
        boolean success = deviceService.save(device);
        if (success) {
            return Result.success(device);
        }
        return Result.error("添加失败");
    }
    
    /**
     * 更新设备
     * PUT /api/devices/{id}
     */
    @PutMapping("/{id}")
    public Result<Device> update(@PathVariable Integer id, @RequestBody Device device) {
        device.setId(id);
        boolean success = deviceService.updateById(device);
        if (success) {
            return Result.success(device);
        }
        return Result.error("更新失败");
    }
    
    /**
     * 删除设备
     * DELETE /api/devices/{id}
     */
    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Integer id) {
        boolean success = deviceService.removeById(id);
        if (success) {
            return Result.success();
        }
        return Result.error("删除失败");
    }
    
    /**
     * 查询在线设备
     * GET /api/devices/online
     */
    @GetMapping("/online")
    public Result<List<Device>> listOnline() {
        List<Device> devices = deviceService.findOnlineDevices();
        return Result.success(devices);
    }
    
    /**
     * 根据名称搜索
     * GET /api/devices/search?name=xxx
     */
    @GetMapping("/search")
    public Result<List<Device>> search(@RequestParam String name) {
        List<Device> devices = deviceService.findByNameLike(name);
        return Result.success(devices);
    }
}
```

# 第四章 避坑指南——项目初始化阶段最容易犯的6个错误

## 错误一：数据库字符集不一致

**症状**：插入中文数据时报错，或查询结果中文显示为乱码。

**原因**：数据库、表、连接的字符集不一致。

**解决方案**：

```sql
-- 1. 检查数据库字符集
SHOW CREATE DATABASE iot_device_db;

-- 2. 修改数据库字符集
ALTER DATABASE iot_device_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 3. 修改表字符集
ALTER TABLE devices CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

在application.yml中指定字符集：
```yaml
url: jdbc:mysql://localhost:3306/iot_device_db?useUnicode=true&characterEncoding=utf8
```

---

## 错误二：MyBatis-Plus版本冲突

**症状**：启动报错`java.lang.NoSuchMethodError`或`ClassNotFoundException`。

**原因**：MyBatis-Plus版本与Spring Boot版本不兼容。

**解决方案**：

| Spring Boot版本 | MyBatis-Plus版本 |
|----------------|-----------------|
| 2.7.x | 3.5.3 - 3.5.5 |
| 3.0.x | 3.5.5+ |

检查pom.xml中的版本号，确保兼容。

---

## 错误三：端口占用

**症状**：启动报错`Port 8080 already in use`。

**原因**：8080端口被其他程序占用。

**解决方案**：

**方法1：修改端口**
```yaml
server:
  port: 8081
```

**方法2：关闭占用端口的程序**
```bash
# Windows
netstat -ano | findstr :8080
taskkill /PID 进程ID /F

# Mac/Linux
lsof -i :8080
kill -9 进程ID
```

---

## 错误四：Maven依赖下载失败

**症状**：pom.xml中依赖报红，或启动报错找不到类。

**原因**：Maven仓库连接超时，或本地仓库缓存损坏。

**解决方案**：

**方法1：配置阿里云镜像**

在Maven的settings.xml中添加：
```xml
<mirror>
    <id>aliyun</id>
    <mirrorOf>central</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

**方法2：清理并重新下载**
```bash
mvn clean
mvn dependency:purge-local-repository
mvn install
```

---

## 错误五：Git提交了不该提交的文件

**症状**：target目录、.idea目录被提交到Git。

**原因**：.gitignore配置错误或未生效。

**解决方案**：

**方法1：删除已提交的文件**
```bash
git rm -r --cached target/
git rm -r --cached .idea/
git commit -m "chore: 移除不应提交的文件"
```

**方法2：确保.gitignore正确**
```gitignore
target/
.idea/
*.iml
```

---

## 错误六：数据库连接超时

**症状**：启动报错`Communications link failure`或连接超时。

**原因**：MySQL服务未启动，或连接配置错误。

**解决方案**：
