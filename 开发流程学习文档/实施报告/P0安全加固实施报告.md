## 一、本次任务涉及的技术库与用处

本次 P0 安全加固在原有技术栈基础上**新增引入 1 个核心库**，并**深度复用 3 个已有库**的能力完成安全加固目标。下面按"新增 → 复用"顺序说明。

### 1.1 新增技术库

#### 🆕 Flyway（数据库版本化迁移工具）

| 维度 | 说明 |
|:-----|:-----|
| **Maven 坐标** | `org.springframework.boot:spring-boot-starter-flyway` + `org.flywaydb:flyway-mysql` |
| **官方文档** | https://documentation.red-gate.com/flyway/ |
| **本次版本** | 由 Spring Boot 4.0.6 父 POM 统一管理 |
| **引入位置** | [pom.xml](file:///d:/code/iot-platform/pom.xml) |
| **配置位置** | [application.yaml](file:///d:/code/iot-platform/src/main/resources/application.yaml) `spring.flyway` 节点 |

**核心用处**：

1. **数据库 Schema 版本化管理**：通过版本号命名的 SQL 脚本（V1、V2、V3...）记录每次数据库结构变更，解决"DDL 散落在 SQL/ 目录手动管理、不可追溯"的问题。
2. **自动化迁移**：应用启动时自动检测并执行未应用的迁移脚本，保证开发、测试、生产环境数据库结构一致。
3. **基线（Baseline）机制**：对已有数据库建立基线版本，后续迁移从基线开始增量执行，兼容存量项目。
4. **迁移历史表**：自动创建 `flyway_schema_history` 表记录每个脚本的执行状态、耗时、校验和，便于审计与排错。

**本次使用方式**：

```
src/main/resources/db/migration/
├── V1__init_schema.sql              # 初始表结构（CREATE TABLE IF NOT EXISTS）
├── V2__add_business_indexes.sql     # 业务查询索引
└── V3__add_deleted_columns.sql      # 为现有表补加 deleted 字段
```

**⚠️ Spring Boot 4 关键注意事项**：

Spring Boot 4 实施了**模块化自动配置**（Modular Auto-Configuration），将原本单一的 `spring-boot-autoconfigure` 大 jar 拆分为多个聚焦模块。**仅引入 `flyway-core` 不再足以触发自动配置**，必须使用 `spring-boot-starter-flyway` starter 才能引入 `spring-boot-flyway` 自动配置模块。这是本次实施过程中踩到的关键坑。

参考：[Spring Boot 4 Modularization](https://www.danvega.dev/blog/spring-boot-4-modularization)

### 1.2 复用的已有技术库

#### 🔄 MyBatis-Plus（逻辑删除能力）

| 维度 | 说明 |
|:-----|:-----|
| **Maven 坐标** | `com.baomidou:mybatis-plus-spring-boot4-starter` |
| **本次版本** | 3.5.16 |
| **官方文档** | https://baomidou.com/ |

**本次复用的核心能力**：

1. **`@TableLogic` 注解**：标注实体类的 `deleted` 字段为逻辑删除标记字段。启用后：
   - `removeById()` 等删除方法自动转为 `UPDATE ... SET deleted=1`
   - 所有查询方法自动追加 `WHERE deleted=0` 条件
2. **全局配置**：在 [application.yaml](file:///d:/code/iot-platform/src/main/resources/application.yaml) `mybatis-plus.global-config.db-config` 中配置 `logic-delete-field`、`logic-delete-value`、`logic-not-delete-value`，实现全局统一。

**本次改动**：

- 5 个实体类（Device、DeviceData、Alert、DeviceType、DictMetric）启用 `@TableLogic` 注解
- DictMetric 实体新增 `deleted` 字段
- 数据库 5 张业务表通过 V3 迁移脚本补加 `deleted` 字段

#### 🔄 Druid（数据源与监控）

| 维度 | 说明 |
|:-----|:-----|
| **Maven 坐标** | `com.alibaba:druid-spring-boot-4-starter` |
| **本次版本** | 1.2.28 |
| **官方文档** | https://github.com/alibaba/druid |

**本次复用的核心能力**：

1. **数据源配置**：通过 `spring.datasource.druid` 节点配置连接池参数
2. **监控面板**：`stat-view-servlet` 提供 `/druid/*` 监控页面
3. **环境差异化配置**：
   - 开发环境（application-dev.yaml）：启用监控面板，弱口令（admin/admin）便于调试
   - 生产环境（application-prod.yaml）：**关闭监控面板**（`stat-view-servlet.enabled: false`），避免暴露

#### 🔄 Spring Boot Profile（多环境配置隔离）

| 维度 | 说明 |
|:-----|:-----|
| **核心机制** | `spring.profiles.active` 激活指定 Profile |
| **官方文档** | https://docs.spring.io/spring-boot/docs/4.0.6/reference/html/features.html#features.profiles |

**本次复用的核心能力**：

1. **配置文件分离**：
   - `application.yaml`：公共配置（Profile 激活、Jackson、Flyway、MyBatis-Plus、CORS、定时任务）
   - `application-dev.yaml`：开发环境（数据源、Redis、JWT、日志、Druid 监控开启）
   - `application-prod.yaml`：生产环境（纯环境变量注入、日志降级、Druid 监控关闭）
2. **环境变量占位符**：`${VAR:default}` 语法实现敏感信息从环境变量注入，yaml 中不再硬编码

## 七、踩坑记录

### 7.1 Spring Boot 4 模块化导致 Flyway 不生效

**现象**：引入 `flyway-core` + `flyway-mysql` 后启动应用，Flyway 未执行任何迁移，`flyway_schema_history` 表未创建。

**原因**：Spring Boot 4 实施模块化自动配置，将 Flyway 自动配置类移到独立模块 `spring-boot-flyway`。仅引入 `flyway-core` 只提供核心 API，不包含自动配置代码，无法触发 `FlywayAutoConfiguration`。

**解决**：将 `flyway-core` 替换为 `spring-boot-starter-flyway` starter，该 starter 会传递引入 `spring-boot-flyway` 自动配置模块。

**参考**：
- [Spring Boot 4 Modularization](https://www.danvega.dev/blog/spring-boot-4-modularization)
- [Spring Boot 4 Migration Guide](https://github.com/spring-projects/spring-boot/wiki/Spring-Boot-4.0-Migration-Guide)

### 7.2 MySQL 不支持 CREATE INDEX IF NOT EXISTS

**现象**：V2 脚本使用 `CREATE INDEX IF NOT EXISTS` 语法，Flyway 迁移报错。

**原因**：MySQL 不支持 `CREATE INDEX IF NOT EXISTS` 语法（PostgreSQL、SQL Server 支持）。

**解决**：移除 `IF NOT EXISTS` 关键字。Flyway 保证每个版本脚本只执行一次，天然幂等，无需数据库层防重。

### 7.3 V1 脚本 CREATE TABLE IF NOT EXISTS 对存量数据库无效

**现象**：V1 脚本使用 `CREATE TABLE IF NOT EXISTS`，对已有表的数据库，脚本执行但表结构未变更，导致实体类启用 `@TableLogic` 后查询报 `Unknown column 'deleted'`。

**解决**：新建 V3 脚本，使用存储过程实现幂等的 `ALTER TABLE ADD COLUMN`，为 5 张现有表补加 `deleted` 字段。

### 7.4 V2 脚本索引与现有数据库索引重复

**现象**：V2 脚本原计划创建 7 个索引，但数据库中已有 4 个同名唯一索引和 1 个功能重复的组合索引，导致 Flyway 迁移失败。

**解决**：精简 V2 脚本，只保留 2 个真正新增的索引（`idx_alerts_device_handled`、`idx_alerts_level_time`），并在脚本注释中说明已存在索引不重复创建。
