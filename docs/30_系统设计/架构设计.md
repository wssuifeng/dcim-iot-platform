## 2. 系统形态与边界

- **单体自部署**（ADR-001）：一个 Spring Boot 4 进程 + MySQL + Redis + mosquitto 组成 compose 栈，`docker compose up` 即完整系统（FR-C14-01）；无微服务、无水平扩展承诺（非目标），负载能力以压测背书（NFR-01：6 机房 105 设备 @120 样本/s 零失败）。
- **南向协议不做**（ADR-002）：平台只收网关北向 JSON；Modbus/SNMP/BACnet 翻译归现场网关，二进制报文必须前置协议网关（§6）。
- **仿真独立**（ADR-003）：造数职责归 simulator/ 独立进程（:8090），与平台零代码耦合；两级链路（虚拟设备—仿真网关—平台）与真实机房同构（FR-C12）。
- **机房即接入主体**（ADR-005）：创建机房即初始化全套凭证，网关对平台零管理依赖；设备零预置，首包自动注册（ADR-006）。

## 3. 分层结构（配 后端模块架构图.html）

### 3.1 入口与横切层

- `controller/`：20 个 REST 控制器（Swagger 注解为契约事实来源，见接口设计文档）。
- `security/`：JWT 过滤链、三角色 RBAC（ADMIN/OPERATOR/VIEWER，role 写入 JWT）、WebSocket STOMP 鉴权与用户隔离推送、账号锁定（Redis 滑动窗口）。
- `common/`：`Result<T>`/`ResultCode` 统一响应、`BusinessException` + `GlobalExceptionHandler`、`@AuditLog` 审计切面、IP 限流过滤器、XSS 过滤器。

### 3.2 数据入口层（ingest 包，四入口 → 传输无关核心）

- 适配器：`ingest/http/`（GatewayAuthenticationFilter 验签 + IngestHttpController / TelemetryCompatController / IngestExportController / PayloadMappingController / IngestMetricsController）、`ingest/mqtt/`（IngestMqttListener 订阅四类 topic + broker dynamic-security 鉴权对接）。
- 传输无关核心：`ingest/service/`（IngestCoreService 五步链，§4.1）+ `DeviceTypeInferencer`（类型智能推断）。
- 映射模板：`ingest/template/`（PayloadTranslationEngine：特征匹配 + 字段路径转译，ADR-009）。

### 3.3 业务域层

- `service/` + `impl/`：设备、指标采样/最新值/聚合/保留策略、告警模版、告警评估（AlarmEvaluateService）、告警状态机（AlarmEventService）、通知分发（AlarmDispatchService）、网关凭证、离线检测、审计。
- `task/`：7 个定时任务——设备离线检测（5min）、网关离线检测（5min）、指标 TTL 清理、小时聚合、分区供给（每日）、幂等键清理、停报超窗确认恢复（5min）。

### 3.4 数据与配置层

- `entity/`、`mapper/`：MyBatis-Plus 实体与 Mapper；表结构事实来源 = Flyway V1–V25（见数据库设计文档）。
- `config/`：Security、Redis（CacheService 统一缓存门面）、MyBatis-Plus（分页）、Async（评估/分发线程池）、ProductionSafetyGuard（生产启动门控）。

### 3.5 前端（Vue 3）

- 路由 RBAC 守卫 + 日/夜双主题；15 个视图：驾驶舱、机房管理、全局告警流、跨机房检索、机房工作台（概览/设备与数据/告警三 tab）、告警模版、指标字典、零散设备接入（ADMIN）、设备类型、用户管理（ADMIN）、审计日志、登录/注册、告警通道（ADMIN）。
- 实时链路：WebSocket（STOMP）订阅个人队列 → 告警弹窗（级别色带 + 音效可静音）+ 头部铃铛。

### 3.6 仿真服务（simulator/，独立进程独立构建）

- 虚拟 Modbus TCP 设备（5 类预设 + 双层环境物理引擎）+ 智能网关（FC03 轮询/工程量解码/周期-死区-越限上报/MQTT-HTTP 双传输）。
- 网关零管理依赖：只配平台地址 + AK + SK；连通自检、阈值拉取（顺带同步机房目录）。

## 4. 核心链路设计

### 4.1 数据接收门（四入口 → 五步公共核心）

**公共核心五步**（传输无关，四入口共用）：

| 步 | 环节 | 设计要点 |
|----|------|---------|
| ① | 凭证认证与机房归属校验 | HTTP 走 GatewayAuthenticationFilter（`Authorization: Gateway {AK}:{sha256(SK+rawBody)}`）；MQTT 走 broker dynamic-security + 报文验签；归属不符拒绝 |
| ② | 首包自动注册（可关） | 未知 deviceCode 建档 + DeviceTypeInferencer 按指标编码推断类型 + 类型模版/指标模板零配置跟随（ADR-006）；凭证维度开关 |
| ③ | 幂等去重 | `sha256(deviceCode:pointCode:seq)` 入 ingest_dedup（唯一键）；开放通道无 seq 降级 `+sampleTime`；7 天窗口定时清理 |
| ④ | 采样落库 | 逐条独立事务（批量 ≤200，部分成功合法，逐条结果回传）；metric_sample 月分区（V21） |
| ⑤ | 告警评估与通知（异步） | 事务提交后（AFTER_COMMIT）异步触发 §4.2，不阻塞上报返回 |

**四适配器差异**：HTTP HMAC（同步逐条结果）、MQTT HMAC（QoS 1 + LWT 遗嘱直入网关离线链路）、TB 兼容（四形态解析 + token 鉴权）、MQTT 子凭证（连接层鉴权）。后两条标准解析失败 → 映射模板回退（特征匹配 eq/contains/exists → 字段路径转译 → 回到五步链②；未命中留存原始报文，每凭证最新一条）。

### 4.2 告警评估与状态机

- **模版解析链**：设备 `alarmTemplateId` 优先 → 为空降级类型基础模版（V15）；规则行含三机制（V19：连续越限 breach_count / 变化量 rate_limit+rate_window_sec / 再告警 re_alarm_sec）与恢复迟滞 hysteresis。
- **评估触发**：采样落库事务提交后异步（@Async + AFTER_COMMIT）；对上报采样做该设备生效模版规则阈值评估。
- **级别语义**：1–5（数字越小越紧急）；同点多规则命中取最严重；更严重命中对活动告警升级（ALARM_UPGRADED，升级留痕 + 规则行可配下行动作 webhook，V22——仅升级分支触发）。
- **五态状态机**：TRIGGERED → ACKED → HANDLING → RECOVERED → CLOSED；转移合法性由 AlarmEventService 校验（acknowledge/startHandling/recover/close 人工转移 + autoRecover 自动恢复）；全程写 alarm_state_transition / alarm_handling_record（操作者 + 备注）；事件逻辑删除。
- **恢复三路径**：回归确认（回安全区且恢复确认窗口 quiet-window-sec 内无越限）、停报超窗确认（定时扫描，AlarmQuietWindowRecoveryTask）、人工 recover；离线类型由恢复采样/心跳 autoRecover。数据中断不由恢复链兜底（由 OFFLINE/网关离线链表达）。

### 4.3 通知分发

- 渠道：站内（in_app_notification）、WebSocket 用户隔离推送、邮件、IM webhook 六渠道（alarm_webhook_channel，V20：WECOM_AIBOT/DINGTALK/FEISHU/NTFY/TELEGRAM/GENERIC）、下行动作 webhook（规则行级，仅升级分支）。
- 可靠性：级别过滤、失败重试（1s/5s/30s 退避）、alarm_notification_log 留痕、重复告警去重合并。告警静默与分组聚合挂接点见 §5。

### 4.4 在线观测

- 网关：心跳恒走 HTTP 刷 last_seen；离线判定双路径（MQTT LWT 即时 / 5min 扫描兜底）→ GATEWAY_OFFLINE 告警（网关级，device_id 为空，V13）→ 心跳恢复 autoRecover 闭环。
- 设备：5min 周期扫描 + 模版 OFFLINE 规则（阈值 = 离线分钟数，基础模版 15 分钟，V17）。

## 5. 新增能力设计（本包产出，40 包实施）

### 5.1 告警静默（FR-C7-09，G-014）

- **数据模型**：新表 `alarm_silence_rule`（V26，DDL 见数据库设计文档 §6）——作用域三维度（机房/设备/告警类型，每行恰一维非空，应用层校验）+ 维护窗口（start_time/end_time）+ 原因/启用位/创建人；命中留痕表 `alarm_silence_hit`（可查判据）。
- **评估链挂点（双重检查）**：① 触发决策点——AlarmEvaluateServiceImpl 新建事件与升级判定前查生效静默规则，命中则不创建事件、不升级；② 分发前置点——AlarmDispatchServiceImpl 投递前复查，拦截窗口内的 resend 再告警与竞态漏网事件。两处检查保证"100% 不产生新事件、不发送任何渠道通知"判据。
- **语义细则**：命中静默的采样 streak 计数照常累计（窗口结束若仍越限，满足条件立即触发）；既有活动告警不受影响（状态机与人工处置照常），但其 resend/升级通知被②拦截；窗口结束无需恢复动作，评估自然恢复；过期规则由定时任务置停。
- **管理界面**：配置入口挂告警相关页面（ADMIN/OPERATOR），页面实现归 40 包按前端规范执行。

### 5.2 告警分组聚合（FR-C8-07，G-014）

- **分组键**（v1 固定）：机房 + 告警级别；**聚合窗口**：全局配置 `alarm.group-window-sec`（默认 30s，0 = 禁用聚合直发）。
- **流程**：告警事件分发前进入分组缓冲（Redis，key = room:level，TTL = 窗口）→ 窗口关闭时每组投递**一条合并通知**（首条详情 + 合并数量概要 + 组内最严重级别）——严格满足"每组至多一条站内弹窗/IM 消息，附合并数量概要"判据。
- **时效权衡**（决策留痕）：窗口缓冲引入最多 30s 通知延迟，换取防弹窗轰炸；告警落库时效判据（NFR-05 <5s）不受影响（落库在评估链，不进缓冲）。参考 Alertmanager Grouping（group_wait）模式。
- **实现要点**：窗口关闭用定时冲刷（10s 粒度扫描到期组）；Redis 降级时聚合直发（宁多勿丢）。

## 6. 接入边界（FR-C15-03/04、FR-B-009）

- **支持直连**：MQTT JSON 报文、TB 生态组件（四形态）、自定义 JSON（映射模板转译）——覆盖 ≥70% 真实设备（FR-C15-02，TB SDK 9/9 实测）。
- **必须前置协议网关**：仅支持 Modbus RTU/TCP、SNMP、BACnet、电力 645 等南向协议或二进制透传帧（hex/base64）的设备——经第三方协议转换网关（Modbus→MQTT/JSON）翻译后按标准通道接入；平台不实现南向协议（ADR-002）、不扩展二进制映射（定义变更事项，未裁决前不做）。**不支持设备类型清单**详见接口设计文档 §4（FR-C15-04）。
