## 2. 迁移策略与历史沿革

- **前向演化**：V1–V25 逐版叠加；破坏性变更的既例：V21 为 metric_sample 换分区做全表重建（先改主键 `(id, sample_time)` 再 `PARTITION BY RANGE COLUMNS`）——此类迁移的回滚预案依赖迁移前快照（FR-B-037）。
- **已拆除的历史线**（知悉即可，不在现状模型内）：
  - 多组织域：V2/V6/V7 建（sys_organization、sys_data_scope_assignment、organization_membership、organization_creation/join_application、platform_registration_settings）→ **V10 全部 DROP**，并从业务表删除 organization_id 列；
  - 仿真域：V8 建（simulation_scene 等 4 表）→ **V12 全部 DROP**（造数职责移交 simulator/，ADR-003）。
- **冻结遗留**：`device_point_alarm_rule`（V4 旧告警规则表）——V15 起 `alarm_template/alarm_template_item` 接管，旧表数据冻结保留作迁移源；**V1–V25 中无 DROP 语句，表仍在库中**，代码零引用（评估/离线链路已切新表）。清理动作随下次破坏性迁移窗口一并处理。

## 3. 域模型总览（现状 25 表，五域）

**接入域**（机房即接入主体，ADR-005）
- `sys_cloud_room`（机房，1）—1:1— `ingest_credential`（全套凭证：AK/SK/TB token/MQTT 子凭证，V14 统一、V23/V24 扩展，唯一键各一）
- `ingest_payload_mapping`（映射模板，挂机房，V25）、`ingest_raw_message`（未匹配报文留存，每凭证最新一条）、`ingest_dedup`（幂等键，7 天窗口）

**设备与指标域**（零预置 + 首包注册，ADR-006）
- `device_types`（类型，含基础模版绑定列）—1:N— `devices`（`deviceCode` 全局唯一寻址；`alarm_template_id` 设备级改绑）
- `point_definition`（平台级指标字典）— `device_type_point_template`（类型级指标模板）、`device_point_binding`（设备实际启用指标）

**时序数据域**
- `metric_sample`（采样，V21 月分区，主键 `(id, sample_time)`）、`metric_latest`（最新值快照，唯一键 (device_id, point_id)）、`metric_sample_hourly`（小时聚合，V21）、`metric_retention_policy`（TTL，point_id 空 = 全局默认）

**告警域**
- `alarm_template` —1:N— `alarm_template_item`（规则行：阈值 + 三机制 + 迟滞 + 下行动作 URL）
- `alarm_event`（权威状态机；`device_id` 可空 = 网关级告警）、`alarm_state_transition`、`alarm_handling_record`（全程留痕）
- `alarm_webhook_channel`（IM 渠道，V20）、`alarm_notification_log`（发送日志/去重）、`in_app_notification`（站内通知）

**系统域**
- `sys_user`（三角色 RBAC）、`sys_audit_log`（结构化审计，V5 结构化字段）

## 4. 核心表字段表格（毕设口径）

### 4.1 sys_cloud_room（V2 建，V10 去组织列后现状）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AI | 机房 ID |
| room_name / room_code | VARCHAR(100)/(50) | 名称 / 编码（唯一键原为组织内唯一，V10 后全局唯一语义） |
| location | VARCHAR(200) | 物理位置描述 |
| status | TINYINT | 0 正常 / 1 停用（停删联动拒绝上报，FR-C1-03） |
| create_time / update_time / deleted | — | 审计三件套，逻辑删除 |

> 凭证列不落机房表——全套凭证在 `ingest_credential`（4.5），与机房 1:1（uk_ingest_room）。

### 4.2 devices（V1 建 + V2/V13/V15 增列）

### 4.4 alarm_event（V4 建 + V10/V13 演化）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK AI | 告警事件 ID |
| device_id | INT **NULL**（V13 改可空） | 网关级告警（GATEWAY_OFFLINE）不挂设备 |
| point_id | BIGINT NULL | 触发指标（通用告警为空） |

## 6. 新增表设计（V26 预设计，FR-C7-09 告警静默，40 包实施）

```sql
-- 告警静默规则（维护窗口屏蔽，G-014；作用域三维度，每行恰一维非空——应用层校验）
CREATE TABLE alarm_silence_rule (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    room_id     BIGINT       DEFAULT NULL COMMENT '作用域：机房（三选一非空）',
    device_id   INT          DEFAULT NULL COMMENT '作用域：设备（三选一非空）',
    alarm_type  VARCHAR(50)  DEFAULT NULL COMMENT '作用域：告警类型（三选一非空）',
    start_time  DATETIME     NOT NULL     COMMENT '窗口起',
    end_time    DATETIME     NOT NULL     COMMENT '窗口止',
    reason      VARCHAR(200) DEFAULT NULL COMMENT '静默原因（维护工单等）',
    enabled     TINYINT      NOT NULL DEFAULT 1,
    created_by  BIGINT       NOT NULL COMMENT '创建人（sys_user）',
    deleted     TINYINT      NOT NULL DEFAULT 0,
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_silence_scope (room_id, device_id, alarm_type, enabled),
    KEY idx_silence_end (end_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='告警静默规则（FR-C7-09）';

-- 静默命中留痕（判据"生效全程可查"）
CREATE TABLE alarm_silence_hit (
    id         BIGINT AUTO_INCREMENT PRIMARY KEY,
    rule_id    BIGINT      NOT NULL,
    device_id  INT         DEFAULT NULL,
    point_id   BIGINT      DEFAULT NULL,
    alarm_type VARCHAR(50) DEFAULT NULL,
    hit_time   DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY idx_silence_hit_time (hit_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='静默命中留痕（FR-C7-09）';
```

> 分组聚合（FR-C8-07）无新表：聚合缓冲走 Redis（TTL = 窗口），窗口语义见架构设计 §5.2。

## 7. 容量与保留

- 写入速率锚点：L4 压测 ~120 行/s（24h ≈ 1000 万行，压测报告 §4）；常态单机房 ~1 行/s 无压力。
- 三层结构控制容量：metric_sample（月分区 + TTL 清理）→ metric_sample_hourly（>48h 趋势）→ metric_latest（快照）；保留策略全局/指标级两级（默认 90 天）。
- 已知缺口：小时聚合无补跑水位（FR-B-015）、最新值读改写竞态（FR-B-008）、长趋势尾部缺口（FR-B-019）——修复设计随 40 包实施。
