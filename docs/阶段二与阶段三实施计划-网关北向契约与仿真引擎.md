## 总览

```
┌──────────────────────────┐    HTTP（唯一耦合点）    ┌────────────────────────────┐
│ simulator（独立仓库）      │ ─────────────────────► │ platform（本仓库，单体）      │
│ 独立 Spring Boot 服务      │  ingest 契约 + 机器凭证  │ devices / points / rules /   │
│ ├ 机房环境引擎             │ ◄───────────────────── │ alarm_event / notification   │
│ ├ 虚拟设备（感知→策略→上报）│  设备 CRUD 等管理 API    │ （全部原样复用，零仿真感知）    │
│ ├ 调度器 + 剧本/随机事件    │  （admin JWT，配置注入）  │                              │
│ └ H2 本地配置 + 管理页      │                        └────────────────────────────┘
└──────────────────────────┘
```

**架构总纲**：平台与仿真器是两个独立进程、两个独立仓库。仿真器对平台只有两类调用——数据经 ingest 契约（机器凭证），管理经平台 REST（admin JWT）。**不共享数据库、不共享代码库、不共享任何运行时**；唯一的契约是本文档定义的 HTTP 接口。仿真器是"官方内置诚实网关"的字面实现：它发的每一份数据都走真实网关的完整路径（鉴权、限流、幂等、告警评估）。

两阶段依赖关系：**阶段三的仿真器以"网关"身份走阶段二建的门灌数**，因此阶段二先行。

# 阶段二：设备接入通道（网关北向契约，本仓库）

## 1. 目标与边界

**做什么**：为平台建立独立于用户 JWT 的机器身份通道——网关凭证、机器鉴权过滤器、批量数据上报契约、幂等去重、心跳保活。

**不做什么**（边界，来自 ADR-002）：
- 不实现任何南向协议（Modbus/SNMP/BACnet/DL645 驱动是网关硬件的职责）
- 第一期不做 MQTT（HTTP 先行，MQTT 适配器留接口位，见 §6）
- 不做网关本地告警的事件上送通道（`/ingest/events` 列为未来扩展，见 §7）

**与现有代码的关系**：纯增量。`devices`、`point_definition`、`device_point_binding`、`MetricSampleService`、`AlertRuleEngine`、`alarm_event` 状态机、通知链路全部原样复用——现有"用户态上报"（`POST /metric-samples`）本身就是透传网关模型的等价物。

## 2. 核心设计决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 网关与设备的关系 | **身份解耦**：网关是通信主体（凭证/心跳），设备是数据主体（报文内 deviceCode） | 一台网关替 N 台设备说话；设备模型零改动 |
| 鉴权方式 | `Authorization: Gateway {accessKey}:{signature}`，signature = sha256(secret + rawBody) | 无状态、不依赖用户体系、与 JWT 链完全隔离 |
| 设备寻址 | 报文用 `deviceCode`（全局唯一，V1 已有 UNIQUE 约束）而非数据库自增 id | 真实网关不知道平台的自增主键 |
| 幂等键 | `deviceCode + pointCode + seq`（网关侧单调递增序列号） | 网络重发不产生重复采样 |
| 时间语义 | 报文必带 `sampleTime`（设备时间戳），平台容忍 +5 分钟偏差（复用现有 `SAMPLE_TIME_FUTURE_TOLERANCE_SECONDS`） | 支持断网补传"迟到但有序"的数据 |
| 心跳 | `POST /ingest/heartbeat` 刷新网关级 last_seen_at；设备在线判定继续走现有"收到上报即在线 + 离线检测任务"闭环（D20） | 心跳与数据分离，网关自身掉线可独立观测 |
| 仿真数据追溯 | **凭证级 `simulated` 标记**（推荐）：仿真器用专用凭证，经该凭证入库的数据天然可追溯；备选方案为设备级 `devices.is_simulated` 列 | 平台设备模型零改动；凭证停用即可整体关闭仿真数据源 |

## 3. 数据模型

### 3.1 新增表（V11 迁移）

```sql
-- 网关凭证（机器身份）
CREATE TABLE ingest_credential (
    id             BIGINT PRIMARY KEY AUTO_INCREMENT,
    access_key     VARCHAR(64)  NOT NULL UNIQUE COMMENT '接入标识（明文传输）',
    secret_hash    VARCHAR(100) NOT NULL COMMENT 'BCrypt(secret)',
    gateway_name   VARCHAR(100) NOT NULL COMMENT '网关显示名，如"机房A-动环主机01"',
    cloud_room_id  BIGINT       NOT NULL COMMENT '绑定机房（该凭证只能上报此机房设备）',
    simulated      TINYINT      NOT NULL DEFAULT 0 COMMENT '仿真网关标记：1=内置仿真器专用凭证',
    status         TINYINT      NOT NULL DEFAULT 0 COMMENT '0-启用 1-停用（停用即拒绝该网关全部上报）',
    last_seen_at   DATETIME     COMMENT '最近心跳/上报时间（网关自身存活观测）',
    expire_at      DATETIME     COMMENT '凭证过期时间（可空=永久）',
    create_time    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_ingest_room (cloud_room_id),
    KEY idx_ingest_last_seen (last_seen_at)
) COMMENT '网关接入凭证';

-- 上报幂等记录（短生命周期，只挡重发不攒历史）
CREATE TABLE ingest_dedup (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    dedup_key   VARCHAR(128) NOT NULL COMMENT 'sha256(deviceCode:pointCode:seq)',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_ingest_dedup (dedup_key)
) COMMENT '上报幂等去重（TTL 清理，与 metric 保留策略联动）';
```

**设计说明**：
- 凭证绑定机房而非单设备——真实网关接管整个机房，设备增减不需要动凭证；服务端校验"设备所属机房 == 凭证绑定机房"，防凭证越权上报其他机房的数据。
- `ingest_dedup` 用唯一索引做硬幂等，`DataCleanupTask` 按保留窗口清理（参照 notification_log 去重表 48h TTL 的既有模式）。评估过 Redis SETNX 方案：批量上报下 Redis 与 DB 双写一致性复杂，DB 唯一索引 + 捕获 DuplicateKeyException 静默跳过更简单可靠。

### 3.2 现有表零改动

`devices` / `point_definition` / `device_point_binding` / `metric_sample` / `metric_latest` / `alarm_event` / 规则表 / 通知表——**全部不动**。网关通道只是 `saveSample` 的一个新调用方。

## 4. 模块架构与依赖

```
新增（src/main/java/com/example/platform/ 下）：
security/GatewayAuthenticationFilter.java      # 机器鉴权过滤器（SecurityFilterChain 挂载，仅拦 /ingest/**）
controller/IngestController.java               # POST /ingest/samples + /ingest/heartbeat
service/IngestCredentialService(+Impl)         # 凭证 CRUD、校验、last_seen 刷新
service/IngestService(+Impl)                   # 上报编排：幂等→归属校验→批量落库
dto/IngestSampleBatchDTO / IngestSampleItemDTO / IngestResultVO
entity/IngestCredential / mapper/IngestCredentialMapper
entity/IngestDedup / mapper/IngestDedupMapper
controller/IngestCredentialController.java     # /ingest-credentials 凭证管理（ADMIN 专属）
```

调用链：

```
SecurityConfig（/ingest/** permitAll + GatewayAuthenticationFilter 强认证）
   → IngestController
      → deviceCode/pointCode 解析（复用现有 Service 查询）
      → 机房归属校验：device.cloudRoomId == credential.cloudRoomId，越权条目 failed
      → IngestService
         ① ingest_dedup 唯一索引插键（重复→跳过计数）
         ② 映射 MetricSampleDTO
         → MetricSampleService.saveBatch(items, credentialId, triggerAlarm=true)
            （currentUserId 参数在单租户下仅用于存在性检查与审计，
              网关传 credentialId 即可复用；审计 actor 记 "gateway:{accessKey}"）
      → （现有链路不变）saveSample → metric_latest → 设备在线刷新
         → MetricSampleSavedEvent(AFTER_COMMIT) → AlertRuleEngine → alarm_event → 通知
```

**SecurityConfig 改动**：`/ingest/**` 加入 permitAll，由 GatewayAuthenticationFilter 接管鉴权（凭证无效 401 + 新增 INGEST_* 错误码段 4095-4098）。过滤器只对 `/ingest/**` 生效，不与用户 JWT 链交叉。

**前端**：新增"接入管理"页（凭证列表/创建/启停/重置 secret，展示 last_seen_at 与 simulated 标记判断网关存活），ADMIN 专属路由，参照 cloud-room/index.vue 的 CRUD 模式。

## 5. 上报契约（接口定义）

> 本节即平台与仿真器（及任何第三方网关）之间的**唯一接口契约**，双方仓库各自实现，修改需双方同步。

```jsonc
POST /api/ingest/samples
Authorization: Gateway {accessKey}:{signature}     // signature = sha256(secret + rawBody)
Content-Type: application/json

{
  "items": [                                        // 单批 ≤ 200 条
    {
      "deviceCode": "UPS-ROOM1-A",                  // devices.device_code
      "pointCode": "temperature",                   // point_definition.point_code
      "value": 22.5,
      "sampleTime": "2026-09-01T12:00:05",          // 设备时间戳（必填，+5min 容差）
      "seq": 10023                                  // 网关侧单调递增，幂等键成分
    }
  ]
}

// 响应
{ "code": 200, "data": { "accepted": 198, "duplicated": 2, "failed": 0, "failures": [...] } }
```

```jsonc
POST /api/ingest/heartbeat        // 网关存活保活（如 60s 一次），仅刷新 last_seen_at
{ "ts": "2026-09-01T12:00:00" }
```

**语义要点**（写入 Swagger description）：
- 逐条独立事务（复用 saveBatch 的 D10 编程式事务模式），部分成功合法；
- 重复 `deviceCode+pointCode+seq` 计入 `duplicated` 而非报错——网络重发是常态；
- `sampleTime` 早于平台时间不拒绝（补传合法），晚于 +5 分钟拒绝（复用现有校验）；
- deviceCode 未注册 → 该条 failed（错误码 DEVICE_NOT_FOUND），不阻塞同批其他条目。

## 6. 技术选型

| 项 | 选型 | 说明 |
|----|------|------|
| 传输 | HTTP（Spring MVC 现有栈） | 无新增依赖 |
| 鉴权哈希 | Spring Security Crypto（已有）+ JDK SHA-256 | 无新增依赖 |
| 幂等 | DB 唯一索引 + DuplicateKeyException 捕获 | 见 §3.1 说明 |
| MQTT（二期） | 独立传输适配层：新增 `/ingest/mqtt` 入口把 MQTT 消息体转投 IngestService | 引入 spring-integration-mqtt 时实现，契约层零改动 |
| 限流 | 复用 RateLimitFilter（Redis 滑动窗口） | dev profile 已放宽 |

## 7. 未来扩展（记录不做）

- `/ingest/events`：网关本地告警事件上送通道（SNMP TRAP 等价物），`alarm_event` 加 `source` 字段（PLATFORM_RULE/GATEWAY_REPORT），按 deviceId+alarmType 关联去重——等真实智能网关接入需求出现再做。
- 拉模式（平台轮询网关）：文档对比项，永不默认实现。
- v1.0 `device-data` 用户态 API 退役：阶段二验收后单独提交删除。

## 8. 实施步骤与验收

| 步骤 | 内容 | 产出 |
|------|------|------|
| S1 | V11 迁移 + 实体/Mapper | ingest_credential / ingest_dedup |
| S2 | IngestCredentialService + GatewayAuthenticationFilter + SecurityConfig 挂载 | 机器鉴权链 |
| S3 | IngestController + IngestService（幂等/归属校验/批量落库） | 上报契约 |
| S4 | 心跳端点 + last_seen_at 刷新 | 网关存活观测 |
| S5 | 凭证管理 REST + 前端"接入管理"页 | ADMIN 管理面 |
| S6 | 测试：鉴权/越权/幂等/补传/批量部分失败 | MockMvc 全链集成测试 |

**验收标准**：
1. 伪造/停用/过期凭证 → 401 + INGEST_* 错误码；
2. 同一 `deviceCode+pointCode+seq` 重发三次 → metric_sample 只有一行，响应 `duplicated=2`；
3. 凭证 A（机房1）上报机房2 设备 → 该条 failed，越权不落库；
4. 上报超阈值数据 → 60 秒内 alarm_event TRIGGERED + 站内通知到达；
5. 心跳停止后 last_seen_at 不再刷新，设备在线状态不受影响；
6. `mvn test` 全绿，新增测试 ≥ 15 例。

# 阶段三：独立仿真服务（新仓库）

## 1. 定位与边界

**定位**：独立仓库、独立进程的设备仿真器，扮演"官方内置诚实网关"：
- **纯 HTTP 客户端**——不碰平台数据库，不共享任何代码/配置/运行时；
- **数据通道唯一**：ingest 契约（阶段二 §5），每份数据走真实网关的完整路径；
- **管理通道**：调平台 REST（admin JWT 配置于本服务 application.yaml）完成设备创建等准备工作；
- **自包含**：环境配置/虚拟设备定义/剧本/运行态全部存本地 H2；自带极简管理页（Vue3）。

**不做什么**：
- 不模拟南向通信（网关与现场设备之间的 RS485/Modbus 是真实网关硬件的事，永久出局）；
- 不做多机房环境联动（空调制冷→温度→功耗因果耦合）——YAGNI；
- 不做表达式/脚本引擎定义变化函数——预设枚举+参数即可，避免注入面；
- 不做断网补传（真实网关的网关侧行为，一期不模拟，未来扩展）。

**验收"够了"线**（ADR-003，防镀金）：20 台虚拟设备 × 4 点位连续跑 1 小时无积压；温度剧本触发 60 秒内告警 TRIGGERED；kill 仿真器再启动自动恢复。达标即停。

## 2. 核心设计决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 因果链 | **单向**：环境变 → 设备感知 → 才有数据。事件只改环境函数，绝不直接改设备数值 | 演示时可追溯因果（环境 25℃ 设备报 38℃ 只能来自显式故障注入） |
| 环境作用域 | 挂机房级：同机房所有虚拟设备读同一环境真值 | 与平台 cloudRoomId 资源模型吻合 |
| 采样与上报分离 | 传感器采样周期（如 5s：更新本地值+越限判定）与上报周期（如 60s）独立配置 | 不分离则变化上报/越限即报无从谈起 |
| 确定性 | 环境引擎与随机事件调度器都接受随机种子 | 相同种子两次运行轨迹一致——回归测试与可重复演示的刚需 |
| 设备档案 | 虚拟设备在平台侧是真实 `devices` 行（经平台 REST 创建，凭证 simulated=1），仿真器本地只存"怎么动、怎么报" | 设备名/类型/机房/点位绑定复用平台模型；凭证级追溯，平台零特判 |
| 剧本与旧模型 | 旧 `simulation_*` 表与模块随本仓库**整体退役删除**；剧本（Scenario）作为仿真器本地概念重新实现 | 平台彻底去仿真化；剧本语义（时间线上改环境）在仿真器内更自然 |

## 3. 仿真器数据模型（本地 H2）

```sql
-- 虚拟设备（长驻运行态）
CREATE TABLE virtual_device (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    device_code     VARCHAR(30) NOT NULL UNIQUE COMMENT '平台 devices.device_code（经 REST 创建后回填）',
    cloud_room_id   BIGINT NOT NULL COMMENT '所属机房（环境档案关联）',
    report_mode     VARCHAR(40) NOT NULL DEFAULT 'PERIODIC'
                    COMMENT '上报策略组合（逗号分隔）：PERIODIC / ON_CHANGE / ON_ALARM',
    sample_interval_sec  INT NOT NULL DEFAULT 5    COMMENT '传感器采样周期（秒）',
    report_interval_sec  INT NOT NULL DEFAULT 60   COMMENT '上报周期（秒，PERIODIC 模式）',
    change_deadband      DECIMAL(10,4)             COMMENT '变化死区（ON_CHANGE）',
    noise_amplitude      DECIMAL(10,4) DEFAULT 0   COMMENT '传感器噪声幅度',
    fault_mode      VARCHAR(20) NOT NULL DEFAULT 'NONE'
                    COMMENT '故障注入：NONE / SENSOR_STUCK(值冻结) / SENSOR_DEAD(停报) / OFFLINE(失联+心跳停)',
    next_sample_at  DATETIME COMMENT '下次采样时刻（调度排序依据，崩溃恢复用）',
    next_report_at  DATETIME COMMENT '下次上报时刻',
    status          TINYINT NOT NULL DEFAULT 0 COMMENT '0-运行 1-暂停',
    create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 机房环境档案
CREATE TABLE room_environment_profile (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    cloud_room_id   BIGINT NOT NULL UNIQUE COMMENT '所属机房',
    seed            BIGINT NOT NULL DEFAULT 42 COMMENT '随机种子（确定性回放）',
    create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 环境通道（机房内每个点位一条：真值如何随时间变化）
CREATE TABLE environment_channel (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    profile_id      BIGINT NOT NULL COMMENT '所属环境档案',
    point_code      VARCHAR(50) NOT NULL COMMENT '平台 point_definition.point_code',
    func_type       VARCHAR(20) NOT NULL DEFAULT 'CONSTANT'
                    COMMENT '变化函数：CONSTANT / SINUSOID(日夜周期) / RAMP(斜坡) / STEP(阶跃)',
    base_value      DECIMAL(10,4) NOT NULL COMMENT '基准值',
    amplitude       DECIMAL(10,4) DEFAULT 0 COMMENT 'SINUSOID 振幅',
    period_sec      INT DEFAULT 86400 COMMENT 'SINUSOID 周期（默认 24h）',
    slope_per_sec   DECIMAL(10,6) COMMENT 'RAMP 斜率（值/秒，可负）',
    step_at         DATETIME COMMENT 'STEP 阶跃时刻',
    step_to         DECIMAL(10,4) COMMENT 'STEP 阶跃目标值',
    create_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 剧本（时间线上的环境事件序列，替代原 simulation_scene/step）
CREATE TABLE scenario (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT,
    name         VARCHAR(100) NOT NULL,
    seed         BIGINT NOT NULL DEFAULT 42,
    status       TINYINT NOT NULL DEFAULT 0 COMMENT '0-可用 1-归档',
    create_time  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE scenario_step (
    id           BIGINT PRIMARY KEY AUTO_INCREMENT,
    scenario_id  BIGINT NOT NULL,
    step_order   INT NOT NULL COMMENT '顺序（从1开始）',
    delay_ms     INT NOT NULL DEFAULT 0 COMMENT '相对上一步的延时',
    action       VARCHAR(20) NOT NULL DEFAULT 'SET_CHANNEL'
                 COMMENT '动作：SET_CHANNEL-修改环境通道 / SLEEP-纯延时',
    point_code   VARCHAR(50) COMMENT 'SET_CHANNEL 目标点位',
    func_type    VARCHAR(20) COMMENT '目标变化函数',
    params       TEXT COMMENT '函数参数 JSON（base/amplitude/...）',
    description  VARCHAR(200)
);
```

## 4. 模块架构与依赖

```
仿真器仓库结构（建议名 dcim-simulator）：
├── src/main/java/com/example/simulator/
│   ├── client/
│   │   ├── IngestClient              # HTTP 客户端：签名计算、批量上报、心跳（契约=阶段二§5）
│   │   └── PlatformAdminClient       # 平台管理 REST 客户端（admin JWT 登录、设备创建）
│   ├── environment/
│   │   ├── EnvironmentEngine         # 每机房一个：按通道定义计算 t 时刻各点位真值（纯函数）
│   │   ├── ChannelEvaluator          # 单通道求值：CONSTANT/SINUSOID/RAMP/STEP + 噪声
│   │   └── ScenarioPlayer            # 剧本执行：按 delay 把 SET_CHANNEL 事件写入通道定义
│   ├── device/
│   │   ├── VirtualDeviceSimulator    # 单虚拟设备：采样（环境+噪声→本地值，越限判定）
│   │   │                             #   上报决策（策略组合）、故障模拟（STUCK/DEAD/OFFLINE）
│   │   └── VirtualDeviceRegistry     # 运行态注册表（内存实例 + H2 持久化 next_*_at）
│   ├── schedule/
│   │   ├── SimulationScheduler       # 单调度器：最小堆按 next_sample_at/next_report_at 排序，
│   │   │                             #   到点派发固定线程池执行
│   │   └── RandomEventGenerator      # 随机事件：权重表+冷却期+种子（产出 SET_CHANNEL 事件）
│   ├── lifecycle/
│   │   └── SimulatorLifecycleService # 启动恢复：扫 virtual_device 表重建调度堆；
│   │                                 #   OFFLINE 故障恢复时恢复心跳
│   └── web/
│       └── SimulatorController       # 本服务管理 REST（环境/设备/剧本 CRUD+启停）
├── frontend/                          # 极简管理页（Vue3+ElementPlus，三 Tab）
│   ├── 虚拟设备（启停/策略/故障注入/批量创建）
│   ├── 环境配置（机房×通道的函数编辑）
│   └── 剧本（步骤编排，动作 SET_CHANNEL）+ 运行观测（真值曲线）
└── docker-compose.yml                 # simulator + 可选联动 platform 一起编排
```

调用链（数据流）：

```
SimulationScheduler 到点
  → VirtualDeviceSimulator.sample()                   # 每 sample_interval
      读 EnvironmentEngine.value(roomId, pointCode, t) # 纯函数求值
      + 噪声 → 本地缓存值；越限判定（同步自平台的规则阈值，见下）
  → VirtualDeviceSimulator.decideReport()             # 策略组合判定
      PERIODIC: 到 report_interval 报全部点位
      ON_CHANGE: |当前-上次上报| > deadband 的点位
      ON_ALARM: 越限点位立即报（并加密上报节奏，如 5s）
  → IngestClient.publish(batch)                       # deviceCode/pointCode/value/sampleTime/seq
      ↓ HTTP → 平台 /api/ingest/samples（完整链路：机器鉴权→限流→幂等→落库）
  → （平台侧）saveSample → AlertRuleEngine → alarm_event → 通知
```

**越限判定数据来源**：管理页配置虚拟设备时经 PlatformAdminClient 拉取该设备的告警规则阈值缓存到本地（供 ON_ALARM 判定与"加快上报"决策）；**告警的产生永远在平台侧规则引擎**，仿真器只决定"报什么、何时报"。

**seq 与幂等**：每个 deviceCode 维护内存 AtomicLong 序列号（启动时以当前时间戳为基准），重启不与历史冲突——幂等键天然防重复。

**崩溃恢复**：启动扫 H2 virtual_device 表 status=0 的行 → 按 next_sample_at（过去时刻立即触发一次）重建调度堆。不补宕机期间"本该产生"的数据（未来扩展）。

## 5. 关键实现思路

### 5.1 环境求值是纯函数

`value(channel, t) = base + Σ(函数项)`，无内存状态、不预计算时间线——任意时刻任意回放求值，天然支持"重启后从当前时间继续"（崩溃恢复不需要回放历史）。STEP 的动态性来自事件**修改通道定义**（写 H2），而非函数自带状态。

### 5.2 调度器：最小堆 + 固定线程池

所有虚拟设备的下次采样/上报时刻入最小堆，单线程按堆顶出队派发给固定线程池（如 4 线程）执行，执行完重算 next_*_at 入堆。暂停/恢复 = 堆的移除与重新入队（内存操作），无轮询。

### 5.3 平台侧准备流程（管理页引导）

创建虚拟设备的三步：① 管理页填参数 → ② PlatformAdminClient 调平台 REST 创建 devices 行（拿到 deviceCode）→ ③ 写本地 virtual_device 配置。环境档案按机房创建，通道按点位配置。凭证由管理员在平台"接入管理"页创建（勾选 simulated）后填入仿真器配置。

## 6. 技术选型

| 项 | 选型 | 说明 |
|----|------|------|
| 服务框架 | Spring Boot（与平台同栈） | 降低维护心智；仅 web + data-jpa/mybatis + 无安全 filter 链（自己只做管理页登录，可选） |
| 本地存储 | H2 file 模式 | 零外部依赖，重启数据保留 |
| HTTP 客户端 | Spring RestClient（或 JDK HttpClient） | 签名拦截器自定义 |
| 调度 | JDK `PriorityBlockingQueue` + 单消费线程 + 固定线程池 | 不引入 Quartz——纯内存调度，Quartz 的 DB 持久化调度是过度设计 |
| 求值 | 纯 Java 函数 | 无表达式引擎 |
| 随机 | `java.util.SplittableRandom`（种子化） | 确定性 |
| 管理页 | Vue3 + Element Plus（复用平台前端技术栈与组件习惯） | 极简三 Tab |

| 步骤 | 内容 | 依赖 |

**验收标准**（= ADR-003"够了"线）：
1. 20 台虚拟设备 × 4 点位 × 采样 5s/上报 60s 连续 1 小时：无内存泄漏趋势、调度无积压（next_sample_at 滞后 < 2s）、平台入库速率符合预期；
2. 温度通道 STEP 到 40℃ 剧本 → 60 秒内平台 alarm_event TRIGGERED + 站内通知到达；
3. kill 仿真器再启动 → 虚拟设备自动恢复（无需人工干预）；
4. ON_CHANGE 死区与 ON_ALARM 即报可用集成测试断言（构造环境斜坡，检查上报条数与时机）；
5. OFFLINE 故障注入 → 平台离线检测任务 15 分钟后产出离线告警（复用现有 D20 闭环）；
6. 相同 seed 两次全量运行产出的上报数据序列一致（确定性）；
7. 平台仓库 `mvn test` 全绿、仿真器仓库构建通过。
