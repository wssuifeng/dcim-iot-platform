## S1 · 网关多实例化（dcim-simulator）

**任务卡 S1-1 数据模型与注册表**

- `schema.sql`：`gateway_config` 增 `cloud_room_id BIGINT`（ADD COLUMN IF NOT EXISTS）；
- `GatewayConfig` 实体增字段；
- 新建 `GatewayInstance`（见 03-技术设计 §1.2，字段与三方法从 `GatewayRuntime` 平移）；
- `GatewayRuntime` 改造为注册表 + 调度器：`start/stop/reload/snapshotOf/offlineOf`，每网关独立单线程调度（池上限 16）；
- `SimulatorLifecycleService.reloadGateway` 改走注册表；
- 设备分流：repository 增 `findByStatusAndCloudRoomIdOrderById`；
- 启动回填：`cloud_room_id IS NULL` 的旧配置按"有设备的唯一机房档案"回填。

完成标准：单网关存量环境行为不变（19 台设备照常上报）；`mvn test` 全绿（新增 `GatewayRuntimeMultiInstanceTest` ≥4 例）。

**任务卡 S1-2 REST 契约与缓存分片**

- `GatewayScenarioController`：`/gateways` CRUD + `/{id}/start|stop`；`sync-thresholds/sync-inventory` 增 `gatewayId` 参数（无参兼容第一个网关）；清单同步只含本机房设备（修复全量上报归属失败隐患）；
- static `cachedRooms/cachedThresholds` 移除：阈值入 `GatewayInstance`，机房目录入新组件 `PlatformDirectoryCache`；
- 启动预热改为遍历全部已配置网关。

完成标准：双网关配置下各自 `sync-thresholds` 互不覆盖（单测覆盖）；管理页旧表单仍可工作（兼容端点）。

## S2 · 管理页多机房改造（dcim-simulator）

**任务卡 S2-1 网关列表 UI**

- `index.html` 网关与观测 Tab：单表单 → 网关卡片列表（每卡：机房下拉 + 凭证三元组 + 传输/轮询/上报参数 + 启停开关 + 连通自检 + 阈值拉取）；
- 卡片显示该网关设备数与最近上报状态（来自 `/gateways` 统计）。

**任务卡 S2-2 批量设备工厂**

- 后端 `POST /api/sim/rooms/{cloudRoomId}/device-suite`（03 §2 契约）；
- 前端"机房套件"表单：五类数量 + 编码前缀 + 种子，一键创建并初始化环境档案；
- 创建后提示去对应网关卡片绑定凭证并启动。

完成标准：管理页可完成"建机房（平台侧）→ 建网关（填凭证）→ 建设备套件 → 启动上报"全流程，无控制台报错。

## S3 · 双机房 E2E（两仓库联调）

- 平台侧（管理页）新建第二机房取得凭证；
- 仿真器双网关分别接入；各 10+ 台设备（用 S2 套件）；
- 验证：两机房设备/告警/网关观测独立；A 网关停止 → A 机房网关离线告警触发、B 数据不断流；A 恢复 → 离线告警闭环；
- 测试数据按用户约定处理（E2E 专用机房可保留为常态演示，删除则彻底清理含采样与告警）。

完成标准：上述场景全部走查通过，记录于本任务卡下方追加的验证记录节。

### S3 验证记录（2026-08-29 实测）

- 环境：平台 8081 / 仿真器 8090（MySQL `dcim_simulator_db`，与平台统一 DB 实例）；机房 4（南昌红谷滩-铭万，19 台）+ 机房 70（GW-DC-B，10 台套件）双网关接入；
- **双机房接入**：机房 70 通过 `POST /rooms/70/device-suite` 批量创建 10 台，首包自动注册全部成功，两机房设备/告警/网关观测完全独立；
- **独立启停**：停止机房 4 网关（18:23）→ 机房 4 GATEWAY_OFFLINE 告警 7 分钟后触发（18:31，级别 2），机房 70 数据流全程不断（load-stats qps 持续）；期间 admin 在前端确认告警（ACKED）；
- **恢复闭环**：重启机房 4 网关 → 首次心跳即自动恢复（19:10:33，RECOVERED）——此验证暴露并修复了 `AlarmEventServiceImpl.findActiveEvent` 对 device_id=null（网关级告警）使用 eq null 导致无法去重/自动恢复的真 bug（commit cffe0f7）；
- **数据模型修复**：E2E 暴露 PDU_METER 类型模版缺 voltage_a/current_a（V16 只补了 UPS），存量 PDU 设备上报被拒——V18 迁移补类型清单 + 回填 7 条存量绑定，失败样本归零；
- **存量清理**：发现 3 条历史重复网关配置（单网关时代遗留），回填后产生三重上报，已删除冗余 2 条。

## S4 · 压测档位与负载参数（dcim-simulator）

**任务卡 S4-1 上报分片与客户端统计**

- `maybeReport` 分片发送（≤200 条/批）；
- `NorthboundClient` 内建统计 + `GET /api/sim/load-stats`（按网关：qps/成功率/p95 延迟）；
- 前端网关卡片展示实时负载摘要，管理页顶部"压测档位"预设按钮（常态/高频/风暴，作用于选中网关）。

**任务卡 S4-2 参数边界校验**

- `reportIntervalSec` 下限 1、`pollIntervalSec` 下限 1；风暴档给出确认弹窗（提示平台压力）；
- 网关数上限 16 校验。

完成标准：单测覆盖分片与统计；手动把单网关调至高频档，`load-stats` 能观察到 qps 上升、延迟平稳。
