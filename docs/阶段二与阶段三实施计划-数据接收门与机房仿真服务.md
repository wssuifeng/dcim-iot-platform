## 0. 现实参照与协议选型

### 0.1 真实机房的数据上传链路

```
现场设备                  智能网关（动环主机）                云平台
UPS/电表/温湿度/空调  ──►  南向：Modbus RTU/TCP、SNMP、   ──►  北向：MQTT / HTTPS
RS485 总线、BACnet        BACnet 轮询采集；本地缓存、           批量 JSON 上报、
                         协议翻译、（可选）本地告警             凭证鉴权、告警工作流
```

平台面对的网络端点**永远是网关**；设备与网关之间走本地协议通道；网关聚合后按北向协议上报。身份解耦：网关是通信主体（凭证/心跳），设备是数据主体（报文内标识）。

### 0.2 协议选型结论

**北向（网关 → 云平台），平台数据接收门支持的协议**：

| 协议 | 主流程度 | 本项目处置 |
|------|---------|-----------|
| **MQTT** | IoT 平台接入事实标准（ThingsBoard/EMQX/阿里云 IoT/AWS IoT） | ✅ 一等公民，MQTT 适配器 + mosquitto broker |
| **HTTPS JSON POST** | 自建平台常见，无状态、防火墙友好 | ✅ 一等公民，HTTP 适配器（先行，契约可测） |
| SNMP TRAP / Syslog | 传统动环事件上送 | ❌ 未来扩展（事件通道） |
| TCP/UDP 私有协议 | 厂商私有 | ❌ 永不实现 |

**南向（设备 → 网关），仿真服务内部模拟的协议**：

| 协议 | 现实占比 | 仿真处置 |
|------|---------|---------|
| **Modbus RTU/TCP** | DCIM 南向事实标准（UPS/电表/精密空调/温湿度） | ✅ 仿真 **Modbus TCP**（localhost 真实 TCP + 真实帧格式） |
| SNMP | 带网卡设备 | ❌ MIB 体系过重 |
| BACnet | 楼宇自控 | ❌ 对象模型复杂 |
| DL/T645 等行业协议 | 电水表 | ❌ 网关职责，不模拟 |

**关键架构说明**：ADR-002"平台不做南向协议"依然成立——南向 Modbus 仿真位于**仿真服务内部**（仿真器模拟的就是一台网关，而南向协议是网关的本职），平台仓库对此零感知。

# 第一步：平台数据接收门（本仓库）

## 1. 目标与边界

**做什么**：传输无关的上报处理核心（IngestCore）+ 两个协议适配器（HTTP 先行、MQTT 其次），机器身份（网关凭证）、幂等去重、心跳保活。适配器只做传输层接入，全部业务语义在核心层——**两种协议收到的数据走完全相同的处理路径**。

**不做什么**：南向协议（ADR-002）；网关本地告警事件上送（`/ingest/events` 未来扩展）；私有 TCP 协议。

**与现有代码的关系**：纯增量。`devices`、`point_definition`、`MetricSampleService`、`AlertRuleEngine`、`alarm_event`、通知链路全部原样复用。

## 2. 核心设计决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 网关与设备的关系 | 身份解耦：网关是通信主体（凭证/心跳），设备是数据主体（报文内 deviceCode） | 一台网关替 N 台设备说话；设备模型零改动 |
| 鉴权 | `accessKey + sha256(secret + rawBody)` 签名；HTTP 放 `Authorization: Gateway ak:sig` 头，MQTT 放报文签名字段 | 同一安全模型跨传输复用；MQTT broker 部署于平台私网，逐报文验签 |
| 设备寻址 | 报文用 `deviceCode`（V1 迁移 UNIQUE 已核对） | 真实网关不知道平台自增主键 |
| 幂等键 | `deviceCode + pointCode + seq` | MQTT QoS1 至少一次投递必然产生重复——幂等正是为 QoS1 而生 |
| 时间语义 | 报文必带 `sampleTime`，+5 分钟容差（复用现有常量） | 断网补传"迟到但有序" |
| 心跳 | HTTP 专用端点 + MQTT 遗嘱消息（LWT）刷新/观测 last_seen_at | 网关存活与设备在线分离观测 |
| 仿真数据追溯 | 凭证级 `simulated` 标记 | 平台设备模型零改动；停用凭证即切断仿真数据源 |

## 3. 数据模型

### 3.1 新增表（V11 迁移）

```sql
-- 网关凭证（机器身份）
CREATE TABLE ingest_credential (
    id             BIGINT PRIMARY KEY AUTO_INCREMENT,
    access_key     VARCHAR(64)  NOT NULL UNIQUE COMMENT '接入标识（明文传输）',
    secret_hash    VARCHAR(100) NOT NULL COMMENT 'BCrypt(secret)',
    gateway_name   VARCHAR(100) NOT NULL COMMENT '网关显示名，如"机房A-动环主机01"',
    cloud_room_id  BIGINT       NOT NULL COMMENT '绑定机房（该凭证只能上报此机房设备）',
    simulated      TINYINT      NOT NULL DEFAULT 0 COMMENT '仿真网关标记：1=机房仿真服务专用凭证',
    status         TINYINT      NOT NULL DEFAULT 0 COMMENT '0-启用 1-停用',
    last_seen_at   DATETIME     COMMENT '最近心跳/上报时间',
    expire_at      DATETIME     COMMENT '凭证过期时间（可空=永久）',
    create_time    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    KEY idx_ingest_room (cloud_room_id),
    KEY idx_ingest_last_seen (last_seen_at)
) COMMENT '网关接入凭证';

-- 上报幂等记录（短生命周期）
CREATE TABLE ingest_dedup (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    dedup_key   VARCHAR(128) NOT NULL COMMENT 'sha256(deviceCode:pointCode:seq)',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_ingest_dedup (dedup_key)
) COMMENT '上报幂等去重（TTL 清理）';
```

幂等用 DB 唯一索引 + DuplicateKeyException 捕获（评估过 Redis SETNX：批量场景双写一致性复杂，不值得）；`ingest_dedup` 由 DataCleanupTask 按窗口清理。

### 3.2 现有表零改动

`devices` / `point_definition` / `device_point_binding` / `metric_sample` / `metric_latest` / `alarm_event` / 规则表 / 通知表——全部不动。

## 4. 模块架构与依赖

```
新增（src/main/java/com/example/platform/ingest/ 新包）：
ingest/
├── IngestCoreService            # 传输无关核心：鉴权校验后的批量处理
│                                #   deviceCode/pointCode 解析→机房归属校验→幂等→落库
├── IngestCredentialService(+Impl)  # 凭证 CRUD、签名校验、last_seen 刷新
├── http/
│   ├── IngestHttpController     # POST /ingest/samples、POST /ingest/heartbeat
│   └── GatewayAuthenticationFilter  # 机器鉴权（仅拦 /ingest/**，SecurityConfig 挂载）
├── mqtt/
│   ├── IngestMqttListener       # 订阅 dcim/{accessKey}/samples，验签后转投核心
│   └── MqttIngestConfig         # broker 连接配置（spring-integration-mqtt）
├── entity/IngestCredential + IngestDedup（+Mapper）
├── dto/IngestSampleBatchDTO / IngestSampleItemDTO / IngestResultVO
└── IngestCredentialController   # /ingest-credentials 凭证管理 REST（ADMIN）
```

调用链（两种传输汇入同一条核心链）：

```
HTTP: GatewayAuthenticationFilter 解析头 → 验签 → IngestCoreService
MQTT: IngestMqttListener 收消息 → 从 topic 提取 accessKey → 验签 → IngestCoreService
   │
   ▼ IngestCoreService（逐条独立事务，部分成功合法）
   ① ingest_dedup 唯一索引插键（重复→跳过计数 duplicated）
   ② deviceCode/pointCode 解析 + 机房归属校验（device.cloudRoomId == credential.cloudRoomId，
      越权条目 failed 不落库）
   ③ → MetricSampleService.saveBatch(items, credentialId, triggerAlarm=true)
      （currentUserId 单租户下仅用于存在性检查与审计，传 credentialId 即可；
        审计 actor 记 "gateway:{accessKey}"）
   ④（现有链路不变）saveSample → metric_latest → 设备在线刷新
      → MetricSampleSavedEvent(AFTER_COMMIT) → AlertRuleEngine → alarm_event → 通知
```

**SecurityConfig 改动**：`/ingest/**` permitAll + GatewayAuthenticationFilter 强认证（无效 401 + INGEST_* 错误码段 4095-4098）；MQTT 走独立 TCP 连接不经 Security 链，由监听器自行验签。

**MQTT 部署**：docker-compose 增加 mosquitto（dev 可选，`INGEST_MQTT_ENABLED=false` 时 HTTP 单跑）；broker 监听平台私网；平台订阅 `dcim/+/samples` 与 `dcim/+/heartbeat`，遗嘱 topic `dcim/{accessKey}/lwt` 触发存活观测标记。

**前端**：新增"接入管理"页（凭证 CRUD/启停/重置 secret，展示 last_seen_at、simulated 标记与接入协议），ADMIN 专属路由，参照 cloud-room CRUD 模式。

## 5. 上报契约（两种传输共用同一 JSON Schema）

> 本节是平台与任何网关（真实或仿真）之间的**唯一接口契约**。

```jsonc
// HTTP: POST /api/ingest/samples
//   Authorization: Gateway {accessKey}:{sha256(secret + rawBody)}
// MQTT: 发布到 dcim/{accessKey}/samples，QoS 1
//   报文为 { "signature": "...", "batch": {...} }，signature 同样是 sha256(secret + batchJson)
{
  "items": [                                        // 单批 ≤ 200 条
    {
      "deviceCode": "UPS-ROOM1-A",                  // devices.device_code
      "pointCode": "temperature",                   // point_definition.point_code
      "value": 22.5,
      "sampleTime": "2026-09-01T12:00:05",          // 设备时间戳（必填，+5min 容差）
      "seq": 10023                                  // 网关侧单调递增，幂等键成分
    }
  ]
}

// 响应（HTTP 同步返回；MQTT 发布到 dcim/{accessKey}/ack 回执 topic）
{ "code": 200, "data": { "accepted": 198, "duplicated": 2, "failed": 0, "failures": [...] } }
```

```jsonc
// 心跳（60s 周期）
// HTTP: POST /api/ingest/heartbeat  {"ts": "..."}
// MQTT: 发布到 dcim/{accessKey}/heartbeat（QoS 0 即可）
// MQTT 额外：连接时注册遗嘱 dcim/{accessKey}/lwt，broker 检测断连自动代发
```

**语义要点**（写入 Swagger description）：
- 逐条独立事务（复用 saveBatch D10 编程式事务模式），部分成功合法；
- 重复 `deviceCode+pointCode+seq` 计入 `duplicated` 不报错——QoS1 重发是常态；
- `sampleTime` 早于平台时间不拒绝（补传合法），晚于 +5 分钟拒绝；
- deviceCode 未注册 → 该条 failed（DEVICE_NOT_FOUND），不阻塞同批其他条目。

## 7. 实施步骤与验收

| 步骤 | 内容 | 产出 |
|------|------|------|
| S1 | V11 迁移 + 实体/Mapper + IngestCredentialService | 凭证体系 |
| S2 | GatewayAuthenticationFilter + SecurityConfig 挂载 | HTTP 机器鉴权 |
| S3 | IngestCoreService + IngestHttpController（幂等/归属/批量落库） | HTTP 通道可用 |
| S4 | 心跳端点 + last_seen_at | 存活观测 |
| S5 | mosquitto 容器 + IngestMqttListener（订阅/验签/LWT） | MQTT 通道可用 |
| S6 | 凭证管理 REST + 前端"接入管理"页 | ADMIN 管理面 |
| S7 | 测试：两传输鉴权/越权/幂等（含 QoS1 重发）/补传/部分失败 | MockMvc + EmbeddedBroker |

**验收标准**：
1. 伪造/停用/过期凭证 → 401 + INGEST_* 错误码（HTTP）；MQTT 验签失败消息丢弃并记审计；
2. 同一 `deviceCode+pointCode+seq` 经 HTTP 与 MQTT 各发一次 + QoS1 broker 重投一次 → metric_sample 仅一行；
3. 凭证 A（机房1）上报机房2 设备 → 该条 failed，越权不落库；
4. 任一通道上报超阈值数据 → 60 秒内 alarm_event TRIGGERED + 站内通知到达；
5. MQTT 客户端异常断连 → LWT 触发，前端可见网关离线；HTTP 心跳停止同理；
6. `mvn test` 全绿，新增测试 ≥ 20 例（覆盖双通道）。

# 第二步：机房仿真服务（新仓库 dcim-simulator）

## 1. 定位与边界

**定位**：独立仓库、独立进程的机房仿真系统，内部还原真实两级通信：

- **设备模块**：虚拟设备以 Modbus TCP slave 形态暴露寄存器（真实协议帧、真实 localhost TCP），寄存器值由环境引擎驱动；
- **网关模块**：Modbus TCP master 轮询采集（南向）→ 工程量解码 → 上报策略决策 → 北向客户端推送（第一步的 MQTT/HTTP 契约）；
- 两个模块间**没有任何进程内调用**——全部通信走 Modbus TCP，与真实机房同构；
- 对平台：数据走 ingest 契约（simulated 凭证），管理走平台 REST（admin JWT）；
- 自包含：配置存本地 H2，自带极简管理页。

**不做什么**：SNMP/BACnet 南向仿真（Modbus 已具代表性）；断网 store-and-forward 补传（未来扩展）；网关本地告警判定（透明网关模式，告警归平台——模型 A，见 ADR-002 讨论）。

**验收"够了"线**：20 台虚拟设备 × 4 点位连续跑 1 小时无积压；温度剧本 60 秒内告警 TRIGGERED；kill 仿真器再启动自动恢复。达标即停。

## 2. 核心设计决策

| 决策 | 结论 | 理由 |
|------|------|------|
| 南向通信 | **真实 Modbus TCP**：设备模块起 slave server（localhost 独立端口），网关模块起 master 轮询；最小子集手写（FC03 读保持寄存器，约 200 行，零依赖） | 协议是 DCIM 南向事实标准；帧格式简单可手写；走真实 socket 而非进程内调用，与真实机房同构 |
| 寄存器模型 | 每点位映射 1-2 个 16 位保持寄存器 + 缩放系数（如 raw=round(value×10)，读出 ÷10 还原工程量） | 还原真实 DCIM"寄存器 40101÷10=22.5℃"的工程实践 |
| 因果链 | 单向：环境变 → 设备寄存器变 → 网关轮询读到 → 才有上报。事件只改环境函数 | 演示可追溯因果 |
| 上报策略归属 | **网关模块**持有 PERIODIC/ON_CHANGE/ON_ALARM 策略（真实网关的北向行为）；设备模块只负责"值对不对" | 与真实设备/网关职责划分一致 |
| 采样与上报分离 | 环境引擎按采样周期刷新寄存器（如 1s）；网关按轮询周期采集（如 5s）、按上报周期推送（如 60s） | 三级频率各自独立，变化死区/越限即报才有意义 |
| 确定性 | 环境引擎与随机事件接受随机种子 | 同种子两次运行数据一致——回归测试刚需 |
| 仿真数据追溯 | 凭证级 simulated 标记（第一步已定） | 平台零特判 |
| 平台侧旧模型 | 平台 `simulation_*` 表与模块随本步 S1 **整体退役**（V13 迁移） | 平台彻底去仿真化 |

## 3. 故障注入与现实语义对照

| 故障模式 | 仿真器行为 | 平台侧现象（自动产生，无需特判） |
|---------|-----------|--------------------------------|
| SENSOR_STUCK | 设备模块冻结寄存器写入 | 数据流变为恒值（演示"传感器卡死/漂移"） |
| SENSOR_DEAD | slave server 停止响应 | 网关轮询超时 → 停止上报该设备 → 平台 D20 离线检测 15 分钟后产出离线告警 |
| GATEWAY_OFFLINE | 网关北向客户端断开 + 停止心跳 | 平台 last_seen_at 停滞（MQTT LWT 立即触发）；设备数据中断 |
| BUS_FAULT | 同机房多台 slave 同时无响应 | 批量设备离线（演示"RS485 总线故障"级联） |

## 4. 仿真器模块架构与数据流

```
dcim-simulator（独立仓库）
├── device/                          # 设备模块
│   ├── VirtualDeviceRuntime         # 每设备一个 Modbus TCP slave（localhost:15020+i）
│   ├── RegisterMap                  # pointCode→寄存器地址+缩放系数（config 配置）
│   ├── EnvironmentEngine            # 纯函数求值：value(channel, t) = base + Σ函数项
│   │                                #   CONSTANT / SINUSOID(日夜周期) / RAMP / STEP
│   ├── DeviceSampleLoop             # 按采样周期：环境值+噪声 → 写寄存器
│   └── FaultInjector                # STUCK / DEAD
├── gateway/                         # 网关模块
│   ├── ModbusMaster                 # 轮询调度：逐设备 FC03 读保持寄存器（轮询周期可配）
│   ├── DataDecoder                  # 寄存器→工程量（÷缩放系数）；超时→设备离线标记
│   ├── ReportStrategy               # PERIODIC（到周期报全部）/ ON_CHANGE（死区）/
│   │                                #   ON_ALARM（越限即报+加密节奏，阈值自平台规则缓存）
│   └── NorthboundClient             # MQTT 发布（主）/ HTTP POST（备），seq 生成、心跳、LWT
├── scenario/
│   ├── ScenarioPlayer               # 剧本：按 delay 把 SET_CHANNEL 事件写入环境通道
│   └── RandomEventGenerator         # 随机事件：权重+冷却+种子（产出同 SET_CHANNEL）
├── lifecycle/
│   └── SimulatorLifecycleService    # 启动恢复：扫 H2 重建设备 runtime 与轮询调度
├── client/
│   └── PlatformAdminClient          # 平台管理 REST（admin JWT：设备 CRUD、规则阈值拉取）
├── web/ + frontend/                 # 本服务管理 REST + 极简管理页（三 Tab）
└── H2 本地存储
```

数据流（完整链路）：

```
EnvironmentEngine（纯函数，种子化）
  → DeviceSampleLoop（每 1s：环境值+噪声 → 写本设备寄存器）
  → [真实 Modbus TCP：网关 master FC03 轮询（每 5s）读寄存器]
  → DataDecoder（raw÷10 → 工程量；通信超时 → 设备离线）
  → ReportStrategy（周期/死区/越限判定）
  → NorthboundClient（MQTT QoS1 发布 dcim/{accessKey}/samples，seq 单调递增）
  → [平台第一步的接收门：验签→幂等→落库→告警评估→通知]
```

## 6. 关键实现思路

### 6.1 最小 Modbus TCP 子集（手写，零依赖）

帧格式（MBAP + PDU）：

```
请求：[txId:2B][protoId:2B=0][length:2B][unitId:1B][fc:1B=0x03][startAddr:2B][quantity:2B]
响应：[txId:2B][protoId:2B=0][length:2B][unitId:1B][fc:1B=0x03][byteCount:1B][registers:byteCount]
```

slave 侧：`ServerSocket` + 每连接一线程（设备数量小，够用）解析帧、查寄存器表返回；master 侧：轮询 + 超时判定设备离线。约 200-300 行，单元测试用帧字节断言（确定性）。

### 6.2 环境求值是纯函数

`value(channel, t) = base + Σ(函数项)`，无内存状态、不预计算时间线——任意时刻回放求值，崩溃恢复不需要回放历史。STEP 的动态性来自事件修改通道定义（写 H2）。

### 6.3 三级频率解耦

环境刷新（1s，写寄存器）→ 网关轮询（5s，Modbus 读）→ 北向上报（60s 周期 / 死区触发 / 越限加密到 5s）。三级各自独立配置，模拟真实系统的采样-采集-上报节奏差。

### 6.4 seq 与崩溃恢复

每 deviceCode 维护内存 AtomicLong（启动以时间戳为基准），重启不冲突；启动扫 H2 重建 slave server 与轮询调度（过去时刻的任务立即触发一次），不补宕机期间数据。

### 6.5 平台侧准备流程（管理页引导）

创建虚拟设备：① 管理页填参数（机房/类型/点位）→ ② PlatformAdminClient 调平台 REST 创建 devices 行 → ③ 写本地 virtual_device + register_map，起 slave server。环境档案/剧本/网关配置均本地维护。

## 7. 技术选型

| 项 | 选型 | 说明 |
|----|------|------|
| 服务框架 | Spring Boot（与平台同栈） | 仅 web + data-jpa + scheduling，无 Security 过滤链 |

| 本地存储 | H2 file 模式 | 零外部依赖，重启保留 |

| 管理页 | Vue3 + Element Plus | 三 Tab：虚拟设备/环境配置/剧本与观测 |

## 8. 实施步骤与验收

| 步骤 | 内容 | 依赖 |
|------|------|------|
| S1 | 平台侧收尾：删除 simulation_* 全部遗留（V13 迁移）+ 仿真器仓库初始化（骨架+H2+管理页框架） | — |
| S2 | 设备模块：RegisterMap + Modbus slave server + EnvironmentEngine（4 种函数单元测试） | — |
| S3 | 网关模块：Modbus master 轮询 + DataDecoder（可用 Modbus 调试工具独立验证 slave） | S2 |
| S4 | NorthboundClient（MQTT 主/HTTP 备）+ ReportStrategy 接线 | **第一步完成** |
| S5 | ScenarioPlayer + RandomEventGenerator + 故障注入 | S2 |
| S6 | 管理页三 Tab + 平台准备流程引导 | S4 |
| S7 | 测试：帧级单测、确定性、崩溃恢复、够了线压测 | 全部 |

**验收标准**（= ADR-003"够了"线）：
1. 20 台虚拟设备 × 4 点位 × 环境 1s/轮询 5s/上报 60s 连续 1 小时：调度无积压、平台入库速率符合预期、无内存泄漏趋势；
2. 温度通道 STEP 到 40℃ 剧本 → 60 秒内平台 alarm_event TRIGGERED + 站内通知到达；
3. kill 仿真器再启动 → slave/轮询/上报自动恢复（无需人工干预）；
4. ON_CHANGE 死区与 ON_ALARM 即报可用集成测试断言（构造 RAMP 斜坡，断言上报条数与时机）；
5. SENSOR_DEAD 注入 → 网关轮询超时 → 平台 D20 离线检测 15 分钟后产出离线告警；GATEWAY_OFFLINE 注入 → MQTT LWT 触发平台网关离线标记；
6. 相同 seed 两次全量运行的上报序列一致（确定性）；
7. 平台仓库 `mvn test` 全绿、仿真器仓库构建与测试通过。
