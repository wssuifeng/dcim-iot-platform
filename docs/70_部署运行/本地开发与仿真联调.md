# 本地开发与仿真联调

本指南面向隔离开发环境。平台、前端与仿真器分别启动；使用新建数据库和合成设备，不连接真实业务库。阶段状态以 [总控](../00_总控.md) 为准，本指南不构成生产部署验收。

## 1. 依赖与数据库

JDK 17、Maven、Node.js 22.12+ 或兼容版本、MySQL 9.6、Redis 7。平台与仿真器使用不同数据库。

```sql
CREATE DATABASE iot_device_db CHARACTER SET utf8mb4;
CREATE DATABASE dcim_simulator_db CHARACTER SET utf8mb4;
```

平台通过 Flyway 初始化结构与 dev 种子；仿真器通过自身 schema.sql 初始化。已有同名库时，改用新的测试库并设置对应连接地址，勿覆盖原数据。

## 2. 平台后端

在仓库根目录复制 .env.example 为 .env，填本地测试连接与密码：DB_URL、DB_USERNAME、DB_PASSWORD、REDIS_HOST/PORT；采用 SPRING_PROFILES_ACTIVE=dev。HTTP 联调时 INGEST_MQTT_ENABLED=false，开放注册与真实邮件不属于本次示例。

```powershell
Copy-Item .env.example .env
# 编辑 .env 后，在仓库根目录启动
mvn spring-boot:run
```

默认地址 http://localhost:8080/api；健康检查 http://localhost:8080/api/actuator/health；dev API 文档 http://localhost:8080/api/swagger-ui.html。dev 种子账号 admin / Admin123 仅用于本地演示。

多项目并行时可在当前终端设置 SERVER_PORT；前端 API_TARGET 与仿真器平台地址要同步修改。本轮使用 8089、5189、8099，数据库/Redis 为独立临时实例。

## 3. 前端

另开终端，从仓库根目录执行：

```powershell
cd frontend
npm ci
npm run dev
```

默认 http://localhost:5173。代理默认指向后端 :8080；如后端改端口，在启动前设置 $env:API_TARGET="http://localhost:8089"，前端自身可用 DEV_PORT 配置。

## 4. 仿真器

另开终端，从仓库根目录执行；本模块不自动读取根目录 .env：

```powershell
$env:SPRING_DATASOURCE_URL="jdbc:mysql://localhost:3306/dcim_simulator_db?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true"
$env:SIM_DB_USERNAME="root"
$env:SIM_DB_PASSWORD="填写本地测试数据库密码"
cd simulator
mvn spring-boot:run
```

打开 http://localhost:8090。平台先建机房并保存一次性接入凭证；仿真器新建网关、绑定机房、填实际平台地址与凭证，创建五类设备套件并启动。平台机房需允许自动登记，或预先按统一契约登记设备与指标。

观察 /api/sim/load-stats 的成功/失败计数，再到平台确认设备、最新值与曲线。测试阈值告警时使用合成数据；人工确认、处理、恢复、关闭各有状态记录。只有“进程启动”不能证明这些链路正常。

## 5. Compose 配置的实际覆盖

根 docker-compose.yml 包含 app、mysql、redis、mosquitto，不含前端与仿真器。app 内部数据库/Redis/MQTT 地址已使用服务名，不能使用容器自身的 localhost 访问其他服务。

复制并填写 .env 后，可先执行 docker compose config 校验；具备正常 Docker 环境时再运行 docker compose up -d --build。前端和仿真器仍按上文独立启动。

本轮配置静态校验通过，实际健康端点 /api/actuator/health 在独立进程模式返回 UP；本机 Docker 运行环境故障，Compose 整体启动未验收。现有示例按本地 dev 使用，不能只切换 prod 就视作生产部署：Redis 认证、可信 Origin、密钥、反向代理与通知渠道还需按 ProductionSafetyGuard 和后续部署阶段落实。

## 6. 检查命令与范围

```sh
# 平台：需要测试 MySQL/Redis，环境变量必须指向测试库
mvn -B verify
# 仿真器：从仓库根执行
mvn -B -f simulator/pom.xml verify
# 前端：进入 frontend 后
npm test
npm run build
```
