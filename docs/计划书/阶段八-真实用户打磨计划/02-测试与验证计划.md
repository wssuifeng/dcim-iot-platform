# 02 · 测试与验证计划

> 原则：阶段七的教训是"自己人对自己人 E2E 全绿，主流工具一上来就抓到 4 个缺陷"。
> 因此本计划的核心思路是**把"主流工具实测"固化为常态化验证门禁**，而不是只做一次性验证。

## 一、测试分层

| 层 | 内容 | 现状 | 阶段八动作 |
|----|------|------|-----------|
| L1 单元/回归 | 平台 305+ / 仿真器 79 | 手动跑 | 进 CI（S8-7）；JaCoCo 出覆盖率报告 |
| L2 协议一致性 | Modbus 帧级语义（异常码/流同步/多寄存器/长连接） | 79 例中的帧级用例 | 每次改 slave/网关必跑；边界用例脚本化进 CI |
| L3 主流工具实测 | pymodbus / Node-RED / mosquitto_pub 等真实工具对打 | 一次性验证 | 固化为可重放脚本 + 手册（见 §三） |
| L4 契约/集成 | ingest 契约（幂等/越权/补传/批量 200）、自动注册 | 平台集成测试覆盖 | MQTT 独立客户端补做（docker mosquitto） |
| L5 E2E 场景 | 双机房/离线闭环/告警时效/跨机房检索 | 阶段七已验证 | 阶段八验收演练复用 |
| L6 负载 | L1 常态 / L4 风暴档 | 阶段七报告 | S8-4 分区聚合完成后复跑对比 |

## 三、主流工具验证矩阵（常态化）

### 3.1 南向（仿真器 slave ← 真实 master）

| 工具 | 验证点 | 形态 |
|------|--------|------|
| pymodbus | 值比对（4 设备×全部指标）、越界 0x02、未知从站 0x0B、**同连接混合序列**、长连接（>60s 不掉线） | `scripts/verify_southbound_modbus.py`（已有）纳入 CI：CI 起仿真器 → 跑脚本 → 断言全过 |
| node-red-contrib-modbus | 10~60s 周期持久连接不重连 | 手册化场景（flow JSON 归档 docs） |
| Diagslave/ModbusPal | 交叉对拍（它们的 master 读我们的 slave；我们的 master 读它们的 slave） | 手动，改协议时跑 |

### 3.2 北向（平台 ingest ← 真实网关）

| 工具 | 验证点 | 形态 |
|------|--------|------|
| Node-RED 流（已验证） | 签名/批量/首包注册/类型推断 | flow JSON 归档，验收演练可复用 |
| mosquitto_pub（独立 MQTT 客户端） | MQTT 契约 + LWT + 平台 MQTT listener | **待办**：docker mosquitto 环境补做（阶段七遗留） |
| Telegraf http 输出 | **评估项**：无逐请求 HMAC 能力——若要做需"本地免签模式"，属安全边界变更，走 ADR | 评估报告（不默认做） |
| ThingsBoard 兼容 API | 若 S8-10 立项，用 TB 生态工具对打 | 依赖 ADR-008 |

### 3.3 验收演练清单（阶段八收尾一次性执行）

1. 温度缓升演练：M1 连续越限计数满足后触发（60s 上报周期 × N 次逼近持续时长语义）（S8-1）；
2. 毛刺注入：单点越限不触发 + 阈值附近振荡不反复恢复（M1 计数 + 恢复侧静默窗口）（S8-1）；
3. 钉钉/ntfy 双通道收到告警；拔 webhook 目标观察重试日志（S8-2）；
4. （原 watchdog 静默演练随 S8-3 延后）
5. 30 天趋势查询 <3s + L4 复跑对比（S8-4）；
6. NUT/ESPHome 桥 + 真实型号 profile 接入演示（S8-5/6）。

## 四、质量门禁

- CI 绿（后端/前端/仿真器三套）；
- 仿真器协议边界用例（L2）与 pymodbus 脚本（L3）不许红；
- 新增对外契约（导出接口/webhook/兼容 API）必须带 Swagger 注解与错误码（ResultCode 扩展，禁止硬编码）；
- 压测数据、验证产物按惯例清理（用户评审决定保留）。
