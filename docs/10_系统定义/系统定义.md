# 系统定义 · v1（锚点 · 已冻结）

> 本文件是整个项目的锚点：后续所有需求、设计、任务的合法性都回溯到本文件。
> 判据数据取自存量证据（387 测试用例、压测报告、TB SDK 9/9 实测）。

## 1. 目标用户（具体群体，非虚构个人）

**系统定位（2026-09-04 吸收定位决策）**：对标主流非商业方案的**轻量化数据中心动环监控平台（DCIM）**——功能上够到 ThingsBoard CE 主线五件事（设备接入 / 遥测存储 / 告警规则 / 看板 / 开箱体验），体量上是其零头（单体 compose 栈）；领域专注动环，不做通用 IoT 平台。四大特色锚点：**高兼容性接入**（多通道协议 + TB 报文形态预设 + 自定义报文映射转译）、**多渠道告警**（站内/WebSocket/邮件/IM webhook 五渠道/下行动作）、**专注 DCIM 领域模型**（机房即接入主体，非通用 device 模型）、**内置仿真验证环境**（两级链路同构 + 物理环境引擎）。

反推自 ADR-001（单租户自部署收束）、2026-08-30 社区调研（archive/历史归档/）、README 定位：

- **自建中小型机房（IDC/企业机房/边缘机房）的运维负责人或一体化运维小团队（1~5 人）**——买不起也不想要商业 DCIM 的年费与实施周期，需要一个 `docker compose up` 就能跑起来、界面能看、告警会响的自部署平台；部署条件：一台能跑 Docker 的服务器（或小集群）+ MySQL/Redis；规模：几个到十几个机房、数百台设备量级（压测验证到 6 机房 105 设备 @120 样本/s）。
- **接入侧是"网关 + 零散设备"两类数据源**：机房侧有采集网关（RS485/Modbus 等南向协议由网关翻译，平台只收北向 JSON，ADR-002）；零散侧有只支持固定报文格式的生态组件/第三方设备（TB 生态等，走开放通道 + 自定义报文映射，ADR-008/009）。
- **排除**：多租户 SaaS 运营方（ADR-001 已收束为单租户）、需要平台做南向协议采集的团队（ADR-002）、移动端用户（PC Web 交付）。

## 2. 核心业务功能（系统的存在理由）

| 编号 | 核心功能 | 验收判据（可度量的完成标准） |
|------|---------|------------------------------|
| C1 | 机房接入与凭证生命周期：创建机房即初始化 AccessKey/SecretKey/TB token/MQTT 子凭证，停删联动 | 机房创建后三秒内凭证可用（网关凭签名上报被接受）；停用机房后上报被拒绝 |
| C2 | 网关北向数据接收（HMAC 双通道）：签名校验、机房归属校验、批量 ≤200 逐条独立事务、断网补传 | 非法签名 100% 拒绝；QoS1 重发/断网补传零重复零丢失（幂等键）；部分成功合法且逐条结果可查 |
| C3 | 开放通道接入（TB 兼容遥测 + MQTT 子凭证）：token/账号密码降级鉴权 | TB 四报文形态全支持（T1 简单对象 / T2 时间戳对象 / T3 数组 / E1 device 多子设备扩展，ADR-008）+ TB 官方 Python SDK 实测 9/9 通过（已达成）；开放通道报文与 HMAC 通道汇入同一条核心链路 |
| C4 | 零散设备自定义接入：报文映射模板（特征匹配 + 字段路径转译）+ 未匹配报文留存 + dry-run 预览 | 标准解析失败的报文经模板转译后入库成功率 100%（模板配置正确时）；未命中报文每凭证留存最新一条可查 |
| C5 | 设备零预置纳管：首包自动注册 + 类型智能推断（凭证维度可关） | 未知 deviceCode 首包上报后设备建档并可查询；常见指标编码（如 temperature）推断类型正确 |
| C6 | 指标时序存储：采样落库（月分区）+ 最新值 + 小时聚合 + TTL 保留策略 | 6 机房 105 设备 @120 样本/s 持续压测零失败（L4 档，已达成）；30 天跨度趋势查询 <3s；分区供给失败产生告警 |
| C7 | 告警治理：告警模版（类型/设备两级绑定）+ 五级状态机 + 三机制（streak/windowDelta/resend）+ 级别升级 | 阈值命中到告警事件落库 <5s；模版规则评估命中最严重级别；状态机五态流转全程留痕可查 |
| C8 | 多渠道通知：站内（铃铛/弹窗/WebSocket）+ 邮件 + IM webhook 五渠道 + 下行动作 webhook + 日志去重 | 告警触发后通知按渠道配置到达（渠道启用时）；重复告警按去重规则合并；发送日志可查 |
| C9 | 网关观测：心跳保活 + 离线告警（周期扫描 + MQTT 遗嘱即时）+ 恢复闭环 | 有 MQTT 遗嘱时离线告警即时；无 MQTT 时扫描周期 ≤5 分钟；恢复后告警自动闭环 |
| C10 | 监控前端：机房工作台（概览/设备与数据/告警三 tab）+ 驾驶舱仪表盘 + 跨机房检索对比 + 日/夜双主题 | 三角色权限边界零越权（RBAC 测试全过）；2-4 机房并排对比可用 |
| C11 | 认证与审计：JWT 无状态 + 三角色 RBAC + 账号锁定 + IP 限流 + 邮箱验证注册 + 结构化审计 | 越权访问 100% 拒绝；关键写操作 100% 留审计痕 |
| C12 | 仿真验证环境：dcim-simulator（虚拟 Modbus 设备 + 智能网关，两级链路同构，独立进程） | 仿真器驱动的端到端链路（接入→数据→告警→通知）可复现；45℃ 平滑过渡 4 秒内触发告警（E2E 已达成）；同 seed 两次运行上报序列一致（确定性）；kill 重启后 slave/网关自动恢复；双层物理引擎（室外气象确定性函数 + 室内热湿平衡持久积分，断档补算上限 6h 不重置）；仿真服务测试 74 用例全绿 |
| C13 | 设备寄存器库（T3，阶段九后续卡）：常见真实器件（APC UPS / 精密空调 / PZEM 电表等）的寄存器映射库，选中型号一键带出指标映射与缩放系数，替代"啃寄存器手册半个月" | 首批收录 ≥5 个真实器件型号，且每个型号有权威一手寄存器手册出处（官方文档，信息来源纪律）；选中型号一键创建后网关可轮询出正确工程量。现状：**未实现**（差距 G-009） |
| C14 | 轻量化部署（"轻量"的数字定义）：单体 compose 栈在常态负载下的资源开销与开箱时间 | L1 常态负载（单机房约 20 设备）下 compose 全栈（app+MySQL+Redis+mosquitto）峰值内存 ≤2GB、4 核可跑；从 `docker compose up` 到首条真实数据落库且首条告警触发，按文档操作 ≤30 分钟。现状：**未测量**（差距 G-010，测量方法由 50 包设计） |
| C15 | 真实机房接入范围：明确本项目能接与不能接的设备边界（2026-09-04 代码级调研后新增） | 标准协议（MQTT/TB 生态/自定义 JSON）覆盖 ≥70% 真实设备（已达成，TB SDK 9/9 实测）；通过第三方网关补齐 Modbus/SNMP/串口（架构文档明确此边界方案）；不支持设备类型清单写入接口设计文档（差距 G-004）。**南向协议不实现**（ADR-002），**不自建协议插件框架**（借鉴 JetLinks SPI 但不做） |

规则：数量不设人为上限；每条必须挂可度量的判据，禁止"体验良好"类不可测表述。
**具体的测量方法属于 50_系统测试阶段的职责**——50 阶段依据本表度量标准设计实际测量
方法与用例。存量项目判据取数来源：387 用例、压测报告（archive/计划书/多机房与压测
迭代计划/05-压测报告.md）、TB SDK 实测记录、阶段八手动测试清单。

## 3. 非目标（本版本明确不做的）

反推自 ADR-001/002/003 放弃项与毕设范围边界（docs/毕业设计/00-工作流规划与差距分析.md §2.2）：

| 项 | 排除理由 |
|----|---------|
| 多租户 SaaS / 组织域 | ADR-001：收束为单租户自部署，三角色模型足够；多组织版本封存于 tag `v5.4-saas-final` |
| 南向协议采集（Modbus/SNMP/BACnet 翻译） | ADR-002：平台只做网关北向契约，协议翻译是网关的职责；仿真器侧做了 Modbus 仅用于验证链路 |
| 平台内置仿真/造数 | ADR-003：V12 退役，造数职责归独立仿真服务（simulator/），避免平台与仿真耦合 |
| 移动端 APP / 小程序 | PC Web 交付（毕设范围边界）；移动端通知由 IM webhook 渠道（企微等）间接覆盖 |
| PUE 能效分析、运行报表模块 | 开题报告已移出本版本，留作展望（毕设范围边界） |
| 微服务/分布式架构 | 单体自部署定位；负载能力以压测验证（L4 档）而非水平扩展承诺 |
| 南向设备的零配置"即插即用"发现 | 只承诺北向首包自动注册（C5），设备侧配置仍是网关/映射模板的职责 |
| 规则链可视化编排 | ThingsBoard 主打能力而本版本明确不做：告警规则以模版结构化字段表达（V15/V19 三机制），不做拖拽式规则链 DSL——轻量定位，规则链引擎的复杂度与运维成本超出目标用户需要 |
| 多租户 SaaS | ThingsBoard 有而本版不做：ADR-001 已收束为单租户自部署；租户隔离带来的数据层复杂度与"1~5 人运维团队"场景不匹配 |
| 部件市场 / 生态市场 | ThingsBoard 有而本版不做：不做仪表盘部件的生态分发；看板能力以内置页面交付（驾驶舱/工作台/跨机房检索） |
| 集群水平扩展 | ThingsBoard 有而本版不做：单体自部署定位；负载能力以压测验证（C6，L4 档 120 样本/s）而非水平扩展承诺 |
| 南向协议采集 | ADR-002 已定不实现；真实机房通过第三方 MQTT 网关（Modbus→MQTT 转换器）补齐 |
| 协议插件框架 | JetLinks SPI 协议 jar 热加载有而本版不做：本项目 4 通道 + V25 自定义映射已覆盖 70-80% 场景，引入插件框架增加运维复杂度与安全面，与轻量化定位冲突 |

规则：非目标是本版本宪法，约束本版本，**不承诺永久**——大版本跃迁制定新定义时
可重新评估进入。
