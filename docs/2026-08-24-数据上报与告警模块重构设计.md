## 0. 执行摘要(30 秒上下文)

系统现状存在两套未闭环的冲突架构:v1.0 旧链路(`alerts`/`device_data`/`dict_metric`/JSON 规则,实际在跑)与第四阶段新链路(V3/V4 表+Service 已落地,但 `alarm_event` 零写入入口、告警规则无独立表)。本次重构**删除旧链路全部代码与表、复用新链路已落地结构、补齐两个缺口(`device_point_alarm_rule` 规则表与 `AlarmEventService.trigger` 产生入口)、统一为"采样→评估→分发"三段单向链路**。数据库无真实数据,Flyway 二次基线重置(空库重建)+ dev 种子库。

```text
[HTTP上报/仿真写入]
  → ①业务基础校验(不通过则拒绝,不进事务)
  → T1 采样事务(INSERT metric_sample + UPSERT metric_latest + 刷设备在线状态)
  → 提交后发布 MetricSampleSavedEvent ──单向──▶
  → T2 告警评估事务(独立事务:规则三级降级检索→阈值校验→trigger 去重/升级/自动恢复)
  → 提交后发布 AlarmEventTriggeredEvent ──单向──▶
  → T3 分发(无事务:WS定向摘要→邮件逐人兜底→站内通知,每通道独立写发送日志)
```

**三段铁律**:回滚永远不跨段;依赖单向(采样不 import 评估,评估不 import 分发);表述一律"采样→评估→分发",禁用 ↔。

### 2.3 新建表 DDL

```sql
-- device_point_alarm_rule:点位告警规则(方案A第4实体,本重构核心增量)
CREATE TABLE device_point_alarm_rule (
    id               BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT '规则ID',
    template_item_id BIGINT NOT NULL COMMENT '所属模板指标项(device_type_point_template.id)',
    device_id        INT    DEFAULT NULL COMMENT 'NULL=模板级规则;非空=该设备覆盖规则(优先)',
    point_id         BIGINT DEFAULT NULL COMMENT '关联point_definition;NULL=通用规则(OFFLINE/COMM)',
    rule_type        VARCHAR(20) NOT NULL DEFAULT 'METRIC' COMMENT 'METRIC阈值/OFFLINE离线/COMM通信异常',
    rule_name        VARCHAR(100) NOT NULL COMMENT '规则名(告警文案前缀)',
    operator         VARCHAR(5)  DEFAULT NULL COMMENT 'GT/LT/GE/LE/EQ/NE;OFFLINE/COMM为空',
    threshold        DECIMAL(18,4) DEFAULT NULL COMMENT '阈值;OFFLINE=离线分钟数(1-1440)',
    alarm_level      TINYINT NOT NULL DEFAULT 3 COMMENT '1紧急…5提示,数字小=严重',
    enabled          TINYINT NOT NULL DEFAULT 1 COMMENT '0停用 1启用',
    organization_id  BIGINT NOT NULL DEFAULT 0 COMMENT '冗余自模板项组织归属(设备覆盖规则=设备组织)',
    remark           VARCHAR(200) DEFAULT NULL,
    create_time      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted          TINYINT NOT NULL DEFAULT 0,
    CONSTRAINT fk_rule_template FOREIGN KEY (template_item_id) REFERENCES device_type_point_template(id),
    CONSTRAINT fk_rule_device  FOREIGN KEY (device_id) REFERENCES devices(id),
    INDEX idx_rule_point_device (point_id, device_id, enabled),
    INDEX idx_rule_template (template_item_id),
    INDEX idx_rule_org (organization_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='点位告警规则表';

-- alarm_notification_log:告警发送日志(替代旧notification_log,关联alarm_event)
CREATE TABLE alarm_notification_log (
    id              BIGINT PRIMARY KEY AUTO_INCREMENT,
    alarm_event_id  BIGINT NOT NULL COMMENT '关联alarm_event.id',
    channel         VARCHAR(20) NOT NULL COMMENT 'WEBSOCKET/EMAIL',
    recipient       VARCHAR(100) COMMENT '用户ID或邮箱',
    content         VARCHAR(500),
    status          TINYINT NOT NULL DEFAULT 0 COMMENT '0待发 1已投递 2失败',
    error_message   VARCHAR(500),
    sent_time       DATETIME DEFAULT CURRENT_TIMESTAMP,
    organization_id BIGINT,
    INDEX idx_anl_event (alarm_event_id),
    INDEX idx_anl_org_time (organization_id, sent_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='告警发送日志(已读状态见in_app_notification)';
```

**规则业务校验(Service 层,D18 相关)**:
- point_id 非空时必须属于 template_item_id 所指模板已含点位(错误码 4044);
- 同 template_item_id + point_id + operator 不重复(4043);
- ruleType 与 operator/threshold 组合合法:METRIC 必填 operator+threshold;OFFLINE 的 operator 空、threshold=1~1440 分钟;COMM 两者皆空(4044);
- 规则创建者组织必须等于模板项组织归属:平台级模板(organization_id=0)仅 PLATFORM_ADMIN 可挂规则(4030)。

### 2.4 关系全景

```text
device_types ─1:N─▶ device_type_point_template(org=0平台/org>0组织) ─N:1─▶ point_definition(org双层)
     │                        │ 1:N(经template_item_id)
     │ 1:N                    └──────────▶ device_point_alarm_rule ◀─ device_id 覆盖(可空)
     ▼
  devices(org/room列) ─1:N─▶ device_point_binding ─N:1─▶ point_definition
     │  └─1:N─▶ metric_sample(+receive_time) ─▶ metric_latest(UNIQUE device+point)
     └─1:N─▶ alarm_event(org/room冗余) ─1:N─▶ alarm_state_transition / alarm_handling_record
                    ├─1:N─▶ in_app_notification(source_id=alarm_event.id)
                    └─1:N─▶ alarm_notification_log
```

### 2.5 模板解析顺序(双层)

```text
设备实际生效模板 = 组织级模板(organization_id=设备所属组织)优先,无则降级平台级模板(organization_id=0)
```

### 3.2 横向(数据范围)

所有组织业务查询叠加 `X-Organization-Id` 头 + `sys_data_scope_assignment` 四级范围(PLATFORM/ORG_ALL/ROOMS/READ_ONLY);READ_ONLY 范围者即使角色可写也只读;PLATFORM_ADMIN 组织业务写操作接口层直接拒绝(D26)。

### 3.3 点位/模板可见性(双层)

组织用户可见 = 平台级(organization_id=0)+ 本组织(organization_id=当前组织);组织模板只能引用平台级或本组织点位。

## 7. 定时任务设计

### 7.1 DeviceOfflineMonitorTask(双向扫描)

```java
@Scheduled(cron = "${task.check-device-cron}")   // 留用 0 0/5 * * * ?
public void checkOffline();
```

**方向①该告警的**:阈值解析(findEffectiveRules 的 OFFLINE 规则,设备覆盖优先→模板级→兜底 `task.offline-threshold-seconds`)→ 按"最小生效阈值"粗筛(getOnlineDetection 现有 SQL)→ 逐台按各自生效阈值精判 → `AlarmEventService.trigger`({deviceId, pointId=NULL, alarmType="OFFLINE", level=规则级或默认2, message="设备超过N分钟未上报", org/room 冗余自设备})→ 活动告警唯一键天然去重 → `DeviceService.updateStatus(id, 0)`(D20)。

**方向②该恢复的**:`listActiveByAlarmType("OFFLINE")` → 设备 last_online_time ≥ now−阈值 → `autoRecover(deviceId, null, "OFFLINE")` → RecoveredEvent → T3 摘要(D21)。
