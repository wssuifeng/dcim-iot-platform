# ADR-001: 放弃多组织 SaaS，收束为单租户自部署 DCIM 平台

日期：2026-08-27
状态：已接受（分支 refactor/depivot，基线 tag `v5.4-saas-final`）

## 背景

第四阶段产品化将平台演进为多组织多租户 SaaS 架构：四角色双体系（`role` + `platform_role`）、组织/机房两级资源、四级数据范围（PLATFORM/ORG_ALL/ROOMS/READ_ONLY）、创建/加入组织审批流、`X-Organization-Id` 组织上下文过滤器。

实践证明该架构为每个后续功能持续引入越权防护成本：v5.4 一轮提交全部用于修复该体系产生的漏洞（READ_ONLY 被放大为可写、平台管理员穿透业务数据、告警收件人越权、角色注入）。项目实际使用场景为个人练手与自部署演示，不存在多租户商业诉求。

## 决定

将项目定位收束为**面向自部署的数据中心动环监控平台**：`docker compose up` 即拥有机房、设备、流动数据与会响的告警。删除全部多组织 SaaS 机制。

## 具体变更

- 角色：四角色双体系 → **ADMIN/OPERATOR/VIEWER 三角色单体系**，JWT 直接携带 role
- 删除：组织/成员/审批流/数据范围/组织上下文过滤器/`/setup` 初始化向导/平台注册策略
- 注册：保留邮箱验证码注册，开关改为 `auth.registration-enabled` 配置项（默认开）
- 数据库：V10 迁移删除 6 张组织域表与 10 张业务表的 `organization_id` 列
- 机房从"组织下的资源"变为顶层资源

## 放弃了什么

- 多租户商业叙事。保留多组织版本的 git tag 供追溯。
- 组织粒度的数据隔离。单部署实例即安全边界，由 ADMIN 管理用户与角色。
- 告警收件人按范围解析。收束为广播给全部启用状态的运维角色用户。

## 后续
