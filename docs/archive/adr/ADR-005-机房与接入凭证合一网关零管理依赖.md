# ADR-005: 机房与接入凭证合一，网关零云平台管理依赖

> 状态：已采纳（2026-08-27 定稿，2026-08-28 落地，提交 bc2a063）
> 关联：ADR-002（网关北向契约）、`docs/阶段二与阶段三实施计划`（第一步）、V14 迁移

## 背景与问题

阶段二落地后的模型是"接入管理"独立页签发网关凭证：管理员建机房、再进凭证页选机房建凭证、填网关名、配置管理账号。E2E 联调暴露三个问题：

1. **概念冗余**：机房与凭证是一一对应的强绑定关系（凭证 cloud_room_id NOT NULL），却拆成两个管理对象、两次录入；
2. **网关越界**：仿真器网关配置里出现了平台管理账号/密码——网关为了"预建设备"和"拉阈值"持有了云平台管理员凭证，管理面与数据面混入同一身份；
3. **观测盲区**：从未上线的凭证（配置错误/网络不通）不产生任何告警，且 MQTT 传输下心跳与数据传输耦合，broker 故障即失联。

用户判断：**网关只负责数据上报、数据检测与本地告警；云平台怎么管理（机房、密钥生命周期、类型目录）是平台自己的事**。

## 决策

1. **机房即接入主体**：创建机房同事务初始化该机房配套凭证（数据库级 1:1 唯一约束 `uk_ingest_room`）；停用机房联动停凭证（网关上报立即 401）；删除机房级联删凭证（机房下有设备仍拒绝）。独立的凭证管理页与 `/ingest-credentials` 管理端点全部移除。
2. **网关配置仅三样**：平台地址 + AccessKey + SecretKey。设备预建逻辑删除（由首包自动注册覆盖，见 ADR-006）；平台连通自检改为 Gateway 签名心跳。
3. **阈值松耦合**：云平台提供 `GET /ingest/export/thresholds`（Gateway 签名），网关侧"拉取阈值"导入本地缓存做 ON_ALARM 判定——网关本地告警不运行时强依赖云平台，云平台也不感知网关如何用阈值。
4. **观测补盲**：从未上线的凭证签发超阈值产出"从未上线"告警；网关心跳恒走 HTTP（与数据传输解耦）；MQTT 不可达自动回退 HTTP。

## 后果

- 正面：接入概念从"两个页面对象"收敛为"机房一个"；网关侧零管理依赖，告警判定可离线工作；删除机房的级联语义清晰。
- 负面/约束：同机房多网关场景（未来可能出现冗余双网关）需要重新引入"凭证实例"概念；凭证服务与告警服务存在依赖环，用 ObjectProvider 懒注入打破（启动期无环）。
- 历史包袱：H2 的 gateway_config 保留 admin 列（可空）兼容旧库，实体已删字段。

## 替代方案（已否决）

- **保留独立凭证页作为运维视角**：用户明确否决——概念不干净，合并更彻底。
- **凭证表内嵌进机房表**：改动面更大且 machine 身份与业务资源分离更清晰，未采纳。
