# ADR-003: 仿真引擎重建——从步骤编排到设备仿真器

日期：2026-08-27
状态：已接受（阶段三路线；2026-08-27 修订为独立服务形态）

## 背景

现行仿真模块（scene/step/run）是一次性脚本编排：步骤直接往 metric_sample 写死值（上帝视角），无法模拟真实设备的持续运行。目标是"模拟真实设备运行"：定时上报、异常即报、环境驱动的实时数值。

## 决定

按四层模型重建：

1. **环境引擎**：环境通道（真值+变化函数：恒定/日夜正弦/斜坡/阶跃）挂机房级；因果链单向（环境变→设备感知），事件不直接改设备数值
2. **虚拟设备**：感知（环境值+传感器噪声）→ 上报策略（周期/变化死区/越限即报）→ 走阶段二网关契约灌数（非旁路后门）
3. **事件调度**：随机事件（权重+冷却+可设种子）与剧本编排（复用 scene/step 表改造：事件改环境，设备自己感知）双来源
4. **执行基础设施**：单调度器+时间轮替代一线程一 sleep；运行态持久化与崩溃恢复

仿真数据打标（source=SIMULATED）但不隔离展示；`simulation.write-enabled` 语义调整为"仿真设备是显式设备类型，生产可合法启用"。

## 修订（2026-08-27）：仿真器独立服务化

原方案的"InProcessTransport 进程内直调"路径**删除**。仿真器确定为**独立仓库、独立进程的 Spring Boot 服务**：

- 对平台只有两类调用：数据走阶段二 ingest HTTP 契约（机器凭证），管理走平台 REST（admin JWT）；不共享数据库/代码/运行时
- 环境配置/虚拟设备/剧本/运行态存仿真器本地 H2；自带极简管理页
- 追溯采用凭证级标记（ingest_credential.simulated），平台设备模型零改动
- 平台侧 simulation_* 表与模块随阶段三整体退役删除

理由：①"诚实网关"字面化——仿真数据必经鉴权/限流/幂等完整链路；②进程隔离，kill 仿真器平台无感知；③平台代码库零仿真残留，边界只剩一份契约文档。详细设计见 `docs/阶段二与阶段三实施计划-数据接收门与机房仿真服务.md`。

## 修订 2（2026-08-27）：设备/网关双模块 + 南向 Modbus TCP 仿真

仿真服务内部进一步还原真实两级通信：**设备模块与网关模块分离，二者之间没有任何进程内调用**——设备模块以 Modbus TCP slave 形态暴露寄存器（localhost 真实 TCP、真实 MBAP/FC03 帧、寄存器×10 缩放还原真实工程量换算），网关模块以 Modbus TCP master 轮询采集后按北向协议（MQTT/HTTP）上报平台。

与 ADR-002 的关系：不冲突——"平台不做南向协议"约束的是**平台仓库**；南向 Modbus 仿真位于仿真服务内部，而仿真器模拟的对象就是网关，南向协议本就是网关的职责。上报策略（周期/死区/越限）归属网关模块，与真实网关的北向行为一致。故障注入对齐现实语义：slave 无响应=设备离线（触发平台 D20 检测）、MQTT 遗嘱=网关断连。
