# 环境物理引擎设计——机房环境与设备仿真解耦为两层

> 背景：旧模型里机房环境 = 若干环境通道纯函数（正弦等），设备只是"读通道值+噪声"，
> 设备与机房环境互不影响——空调不会真的降温，服务器发热不存在，环境也不持久。
> 本设计将仿真拆为两层：**室外气象（确定性函数）+ 室内热湿平衡（持久化状态积分）**，
> 设备从室内状态取值，同时以发热/制冷/除湿真实反作用于室内状态。

## 一、室外气象层（WeatherService，确定性、可重放）

- **来源**：`snapshot(seed, 时刻)` 纯函数——同种子同时刻结果恒定，重启无需持久化。
- **季节基线**：南昌月均温曲线（1月5℃ → 7月30℃ → 12月7℃）线性插值，
  日周期 ±3~6℃（峰值约 14:00）。
- **天气型**（Markov 风格的确定性窗口选择，窗口 3~8 小时）：
  SUNNY 晴 / CLOUDY 阴 / RAIN 雨 / STORM 暴雨·季风 / MUGGY 闷热（夏季权重高）。
  各型影响温度修正、日较差系数与湿度基线（雨 90%+、晴 55%）。
- **钳位**：T_out ∈ [−8, 42]，RH_out ∈ [20, 100]（防数值失控，非物理限制）。

## 二、室内热湿平衡层（RoomPhysicsEngine，持久化状态、永不重置）

**状态**（新表 `room_environment_state`，每机房一行）：
室内温度 T_in、室内相对湿度 RH_in、空调运行位、last_tick_at。
首次建档案时初始化：T_in = clamp(当时室外温, 15, 30)，RH = 60。
**此后任何重启都从持久化状态继续积分（catch-up），绝不重置**。

**每秒积分**（断档按 5s 步长补算，上限 6 小时）：

```
净热流 W = 围护导热 UA×(T_out − T_in) + IT 负载 W + 火灾注入 − 空调制冷 W
T_in += 净热流 × dt / 热容量
RH_in += (RH_out − RH_in) × 渗透率 × dt − 空调除湿速率 × dt
常规钳位 T_in ∈ [−5, 55]；火灾演练绕过钳位（上限 120℃）
```

**机房参数**（profile 列，管理页可调）：IT 负载 kW（默认 40，即服务器发热）、
空调额定制冷 kW（60）、温度设定 24℃（±0.5 回差控制）、湿度设定 55%。
空调制冷耗电按 COP=3 折算进入 `power_kw`。

## 三、设备层耦合

- **读取**：物理接管指标（temperature/humidity/supply_air_temp/return_air_temp/power_kw）
  由室内状态派生——送风 = 制冷中 ? T_in−8 : T_in+0.5；回风 = T_in+1.5；
  功率 = IT 负载 + 空调电耗。设备层叠加**确定性偏差**（按 deviceCode+pointCode 哈希，
  温度 ±0.4℃ / 湿度 ±2% / 功率 ±3%）+ 原有噪声，设备间略有差异。
- **反作用**：IT 负载持续加热室内；空调制冷/除湿真实拉低 T/RH；
  空调停机（演练/故障）后机房按净热流升温，约 0.8K/分钟。
- 非环境类指标（电压/电流/电池/负载率/漏水/累计电量）仍走环境通道。

**迁移**：启动时删除各档案下被物理接管的旧通道（temperature/humidity/
supply_air_temp/return_air_temp/power_kw），其余通道不动；通道表单禁止再保存这些指标。

## 四、演练语义变化

| 旧 | 新 |
|----|----|
| 高温演练=温度通道拉 45℃ | **空调停机演练**（IT 发热自然升温）/ **火灾演练**（300kW 注入 120s，可越限至 120℃ 触发平台高温告警） |
| 湿度通道拉 80% | 空调除湿/渗透加湿由物理积分，无需手拉 |
| 温度回落 | **空调恢复** |

## 五、边界

- 室内钳位是仿真护栏（防常规状态数百度攀升），火灾演练是唯一越限通道。
- 补算上限 6 小时：更长的停机视为"接近室外平衡"从 6 小时处接续，避免超长循环。
- 确定性：室外层 (seed,t) 纯函数可回放；室内层含持久化状态，轨迹依赖历史（符合"影响持久化"要求）。

## 六、V2 增强：模拟事件体系与变化值/真实值分离

### 两类模拟事件

**第一类：自然外部事件**（`WeatherService` 自然事件层，自动+可手动注入）
- 事件池（季节加权、6h 确定性窗口、约 25% 概率激活、边界缓动）：
  寒潮（冬，T −10）/ 热浪（夏，T +7、RH −15）/ 连阴雨（雨型强化，RH +10）/
  雷暴（暴雨型强化，T −5）/ 桑拿天（夏，T +2、RH +12）。
- 管理页可手动注入同类事件做演练（内存态、限时自动结束），同样走缓动函数。

**第二类：设备类事件**（事件流，全部以"流/参数斜坡"作用，绝不直接赋值）
- 负载激增：IT 负载临时增量（+30kW，爬坡 10min → 保持 → 卸坡）；
- 空调调温：修改设定值（回差控制天然平滑）；空调停机/恢复；火灾热注入。
- **IT 负载参数全局斜率化**：引擎对 profile 参数以 5kW/分钟斜率追踪，
  任何来源（手动改参/事件）的负载变化都表现为平滑的热流变化。

### 变化值与真实值分离

- **变化值（驱动侧）**：profile 参数（IT 负载 kW、空调设定温/湿度）、
  事件注入热流（火灾 kW、负载激增 kW、自然事件温度修正）、
  无空调平衡温度 T_eq = T_out + 总热流/UA（空调停机时机房的去向）。
- **真实值（状态侧）**：室内 T/RH 持久积分值——由上述变化值经热容惯性演化而来。
- 快照同时暴露两侧，管理页"环境总览"分开展示；事件只写变化值，真实值永远平滑演化。

### 指标中文名

仿真器管理页所有 pointCode/参数渲染时叠加中文名注释（温度/湿度/A相电压/…），
通道配置、实时观测、预设映射一致。
